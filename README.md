# Fast Modbus для MasterSCADA 4D — кандидат для испытаний

Основа: CYNTRON-git/fast_modbus_MasterSCADA4D_driver, commit `8815c7b146551586a65c427f381460b8321ed046`. Подготовка 22.11.2026. Это отдельный кандидат, без установки в рабочую SCADA или на контроллер.

Текущее состояние полного проекта 16 устройств / 554 канала, первого проекта COM4 / 38 каналов и проверки загрузчика ARM — [HIL_READINESS_20261122.md](docs/HIL_READINESS_20261122.md). Исторические результаты ранних кандидатов не заменяют эту сводку и JSON фактических прогонов.

Две обязательные части расширения: библиотечный тип **FastModbus** с `SubTypeName=FastModbus`, наследующий «ФБ протокол», и `mplc_protocol_fast_modbus.dll/.so`. Одна DLL не добавляет тип в палитру IDE. `tools/project/` создаёт отдельный испытательный проект штатным C# API; рабочая база Сколково не используется.

Для сборки ARM на Mac mini используйте `./tools/build_mac.sh /абсолютный/путь/к/новой/сборке`. Журнал, ABI и `work/API/platform/linux/api/mplc_protocol_fast_modbus.so` сохраняются в указанном каталоге. Автономные тесты запускаются через `./build.sh host-tests`.

## Проверяемое поведение

* Формат событий WB: LEN, TYPE, ID big-endian, VALUE little-endian; типы на проводе 1…4, REBOOT=15. В настройке RegType остаются прежние значения 0…3.
* Начальное чтение всех каналов, индивидуальная настройка событий 0x18, проверка битовой маски результата. Неподдержанный канал продолжает циклически читаться. Таймаут настройки не означает, что прибор не поддерживает Fast Modbus.
* Подтверждение только целого проверенного пакета. Повтор определяется по адресу, флагу и содержимому; REBOOT с повторённым флагом не теряется. Следующий минимальный адрес обеспечивает обход нескольких модулей.
* Проверка CRC, адреса, функции, длины и полного эха команды записи. Статус работы и прочитанное значение не подменяются командой.
* U16/I16/U32/I32/F32; Scale/Offset применяются одинаково при первичном чтении, событиях и записи. NaN/Inf и выход за диапазон отвергаются.
* Heartbeat обнаруживает потерю связи даже у каналов без изменений. После восстановления повторяются чтение и подписки. Драйвер выставляет BadCommunicationError; MasterPLC после первого успешного чтения сохраняет последнее значение с качеством UncertainNoCommunicationLastUsableValue (0x408F0000). При подтверждённой связи неизменяющиеся события сохраняют Good, при потере — не Good и Fault.
* Запись выключена по умолчанию. Начальные значения выходов не отправляются. Повторы ошибочной команды ограничены тремя попытками с интервалом; отключение AllowWrites отменяет очередь.
* POSIX serial открыт эксклюзивно, но это **не заменяет lease port coordinator** на SA-02m. В один UART допускается один согласованный владелец.

## Настройки

Протокол (входные параметры; изменения статических настроек требуют перезапуска проекта):

| Имя | Значение по умолчанию / смысл |
|---|---|
| PortName | `/dev/ttyUSB0`; Windows `COMn`; имитатор `tcp://127.0.0.1:15502` |
| BaudRate, Parity, StopBits, DataBits | 9600, 0 (нет; 1 чётная, 2 нечётная), 1, 8 |
| ResponseTimeoutMs, InterFrameDelayMs | 200, 5; задержка добавляется к t3.5 |
| EnableFastModbus | true; false включает обычный RTU |
| EventPollIntervalMs, FallbackPollPeriodMs | 50, 1000 |
| HealthPollPeriodMs, DeviceTimeoutMs | 5000, 15000 |
| MaxTransactionsPerCycle, MaxCycleMs | 8, 100; бюджет проверяется **между** транзакциями; текущая может закончиться позднее |
| AutoScan | false; диагностический scan, без изменения адресов и серийных номеров |
| AllowWrites | false; глобальное разрешение команд |

Обработчик событий поддерживает формат WB и формат МР-02м 1.0.10.38. В старом формате ответ 0x11 использует флаг 0x55/0xAA, точное число элементов и запись с типом, адресом и значением в порядке big-endian. Пустой ответ 0x12 содержит адрес модуля и флаг. Драйвер проверяет CRC, структуру партии и значения дискретных каналов перед подтверждением. При двух допустимых интерпретациях кадра драйвер ждёт следующий пакет. На МР-02м 1.0.10.38 запись подписки может занять строку таблицы даже при совпадении с действующим приоритетом.

Числовые настройки протокола имеют тип **DINT**: INT в SDK 35699 — 16 бит и не вмещает 115200. PortName — STRING, флаги — BOOL. `MPLC_DECLARE_PROPERTIES` должен находиться перед `MPLC_PROTOCOL_TYPE`, иначе таблица свойств не попадает в регистрацию API.

Модуль: `ModbusAddress` 1…247 (старое имя `ModbusAddr` читается как alias), `SerialNumber` 32 bit, `UseSerial` false. Использование серийного номера относится к обычным RTU запросам; события всё равно идентифицируются адресом. Дубли адресов запрещены.

`DisableEvents` (BOOL, default false) задаётся при инициализации модуля. Для обычного Modbus, например Carel c.pCOmini, устанавливается true: драйвер не отправляет этому адресу настройки 0x46/0x18, читает его циклически и не принимает события за источник его значений. Положительный флаг отключения необходим: native-экспорт SDK 35699 исключает false/0 из карты настроек. Старые модули без нового флага сохраняют события. Другие модули той же линии продолжают событийный обмен. UART принадлежит одному экземпляру протокола. При необходимости строго классического RTU задаются также `UseSerial=False` и `AutoScan=False`; широковещательный запрос событий для соседних FMB модулей остаётся общим для всей линии.

`GroupEventRanges` (BOOL, default false) объединяет одиночные каналы одинакового типа и приоритета в диапазон 0x18 длиной до 246 регистров. Промежутки получают DISABLED. Включать только для проверенной карты: в профиле MR 12AI регистры 403, 410, …, 480 объединены, чтобы не исчерпать таблицу из 16 приоритетов с 11 системными записями. Ответные биты проверяются для каждого канала; отказ ёмкости/адреса оставляет циклический опрос до повторной инициализации.

Команды работают по изменению значения: закрытое условие записи удерживает последнее изменение до разрешения; возврат к уже переданному значению отменяет изменение. AllowWrites=False отменяет очередь и отбрасывает изменения за период запрета. Повторная запись того же значения по отдельному импульсу не реализована. Для первого canary выходные каналы не создаются.

Канал:

| Имя | Значения |
|---|---|
| RegType | 0 Coils, 1 Discrete Inputs, 2 Holding, 3 Input |
| RegAddr | Нулевой адрес регистра, 0…65535 |
| Priority | 0 отключены события, 1 LOW, 2 HIGH |
| ValueType | 0 U16, 1 I16, 2 U32, 3 I32, 4 F32 |
| WordOrder | 0 старшее слово первым, 1 младшее; для обычного RTU; event VALUE всегда LE |
| Scale, Offset | Scale обязательно задаётся ненулевым (обычно 1), Offset обычно 0; physical=raw*Scale+Offset |
| Deadband | 0; порог в физических единицах |
| MinIntervalMs, BurstWindowMs, BurstMaxEvents | 0; ограничения публикации в SCADA, не настройки очереди модуля |

Числовые настройки каналов, отсутствующие в native-карте, трактуются как 0: это способ сериализации явно заданного нуля в SDK 35699. Нельзя подставлять вместо отсутствующего RegType значение 3: это превращает Coil в Input Register. Профиль задаёт все настройки явно; отсутствующий/нулевой Scale отвергается.

Диагностика LINT: Requests, Responses, Timeouts, BadFrames, EventPackets, EventValues, DuplicatePackets, ReadRequests, WriteRequests, WriteErrors, RejectedSubscriptions, ScannedDevices. `Timeouts` включает отсутствие событийного ответа; само по себе это не отказ модуля. `Fault`/`ErrorText` модуля определяются проверенными ответами и качеством каналов.

TCP здесь — прозрачный RTU, **не Modbus TCP/MBAP**. Сетевой режим предназначен прежде всего для автономного имитатора. Для событий на физической шине требуется проверенный gateway, сохраняющий арбитраж и кадры.

## Сборка и автономные проверки

Windows, локальный compiler/SDK из подготовленного стенда:

```powershell
python tools/build_windows.py --tests
python tests/transport_tests.py
python tools/build_windows.py
```

Linux host (без SDK): `./build.sh host-tests` — CMake, ASan/UBSan, ctest. Этот путь не запускается на занятом Mac без согласованного слота.

ARM addin собирается **только vendor MPS GCC 13.3.0**, с `libmpsc++.so`. Общесистемный arm-linux-gnueabihf-g++ не подходит. Подготовлен `tools/build_arm_vendor.py`: проверяет закреплённые хеши SDK и compiler, копирует входы в новый каталог, собирает и проверяет ELF/NEEDED/InitAddin. По умолчанию только готовит файлы; `--build` выполняет компиляцию. Ничего не устанавливает и не запускает на ARM.

```bash
./build.sh linux-armv7hf \
  --inputs /readonly-work/inputs/sa-mplc-inputs \
  --work-dir /work/build/fast-modbus-35699-UNIQUE \
  --toolchain /readonly-work/toolchains/arm-mpssoft-linux-gnueabihf --build
```

SDK набора — **1.3.10.35699**, заявленный runtime .135 — **1.3.10.34421**. Успех такой сборки подтверждает только кандидата 35699, не совместимость с 34421. Перед HIL нужен согласованный runtime/SDK либо доказанный ABI и отдельная проба загрузки. В рецепте нет подмены NEEDED, автоматического обновления runtime или обхода этого ограничения.

Матрица и порядок передачи стенда: [docs/HIL_PLAN.md](docs/HIL_PLAN.md). На текущем этапе аппаратные испытания, RS-485 арбитраж, ARM загрузка и длительная работа на реальном runtime не подтверждены.
