# Прошивка модулей MR-02m / MP-02m (Windows)

Настольное приложение для обновления прошивки устройств **MP-02m (MR-02m)** по интерфейсу RS-485 (Modbus RTU) через COM-порт или USB‑RS485 преобразователь.

Соответствует ТЗ: `doc/FLASHER_WINDOWS_TZ.md`, протокол бутлоадера: `doc/BOOTLOADER_WB_TZ.md`.

**Платформа:** Windows (GUI). Прошивки — только локальные файлы (.fw, .bin, .wbfw); выбор порта и устройства вручную. Отличия от прошивальщика Wiren Board (Linux, сервер, автообновление): см. `doc/WB_FLASHER_VS_OURS.md`.

## Требования

- Windows 10/11
- Python 3.8+ (для запуска из исходников)
- COM-порт (встроенный или USB‑RS485)

## Установка

```bash
pip install -r requirements.txt
```

## Запуск

Из **корня проекта** (папка MP-02m):

```bash
python -m flasher_windows.app_gui
```

или:

```bash
python flasher_windows/app_gui.py
```

Файл прошивки ищется в **корневой папке приложения** (папка, где лежит скрипт/исполняемый файл). При запуске из корня проекта — это корень проекта.

## Файл прошивки

Поддерживаются форматы **.fw** (рекомендуется), **.elf** и **.bin**.

- **.fw** — формат бутлоадера (info 32 байт + блоки по 246 байт). Создаётся скриптом `python bootloader/scripts/make_fw.py -i AppBoot/mp-02m.elf -s mp02m -o mp02m.fw`. **Используйте только образ, собранный конфигурацией AppBoot** (линкер **STM32F030CCXX_FLASH_boot.ld**, ORIGIN **0x08000800**). Сборка: `make AppBoot` в корне проекта. Debug/Release используют FLASH.ld (0x08000000) — такой образ прошивальщик отклонит.
- **.bin** — сырой образ под адрес 0x08000800 (только из сборки AppBoot).
- **.elf** — из образа извлекаются сегменты по 0x08000800 (только AppBoot).

Имя: **`MR-02m_<версия>.elf`** / **`.bin`** или **`mp02m.fw`** / **`mp02m_1.0.0.fw`**. Расположение: корневая папка приложения (рядом с исполняемым файлом или скриптом).

## Краткая инструкция

1. **COM-порт** — выберите порт из списка, при необходимости нажмите «Обновить список портов».
2. **Сканировать** — поиск устройств на линии (сначала широковещательный запрос, затем адреса 1–247). Найденные устройства отображаются в таблице.
3. **Устройство для обновления** — введите **Modbus-адрес** (0–247) или **серийный номер** (десятичный или 0x…) устройства из таблицы.
4. **Файл прошивки** — автоматически ищется в папке приложения; при нескольких файлах можно выбрать через «Обновить список / Выбрать».
5. **Сигнатура устройства** — по умолчанию `mp02m` (до 12 символов); должна совпадать с сигнатурой в EEPROM устройства.
6. **Обновить** — прошить одно выбранное устройство.
7. **Обновить все** — последовательно прошить все устройства из таблицы (с возможностью пропустить при ошибке).
8. **Отмена** — прервать текущее сканирование или прошивку.

## Серийные номера

Серийный номер хранится в Flash по адресу **0x080000C4**, 4 байта, little-endian. В блоке «Серийные номера» можно задать **начальный №**; при «Обновить все» или «Только присвоить серийные» номера присваиваются по порядку (через регистр 1005 бутлоадера).

**Серийная прошивка через ST-Link** (прищепка, аналитика, счётчики успех/брак/отказ) вынесена в отдельное приложение: **`production_flasher_stlink/`** (см. его README).

## Обнаружение и протокол прошивки

- **Обнаружение устройств** — по Modbus RTU: сканирование адресов 1–247, при необходимости broadcast (адрес **255** только; 0 не поддерживается).
- **Прошивка** — по протоколу бутлоадера (тот же UART): скорость **115200 8N1**, запись в регистры 0x1000 (info) и 0x2000 (блоки данных).

## Сценарий прошивки

1. При необходимости: запись **1** в регистр **129** (переход в бутлоадер) → ожидание ~1 с (перезагрузка).
2. Открытие порта на **115200 8N1**, пауза ~1.5 с (инициализация бутлоадера).
3. Опционально: чтение reg 290/330 (сигнатура, версия загрузчика).
4. Отправка **info-блока** (16 регистров по адресу 0x1000): сигнатура и размер прошивки.
5. Ожидание **2 с** (стирание Flash на устройстве).
6. Отправка **блоков данных** по адресу 0x2000: приложение — 123 reg (246 B); образ бутлоадера — 122 reg (244 B), 142 полных блока + 1 последний 84 reg (168 B).
7. Запись в регистр **1004** — переход в приложение.

## Обновление бутлоадера

**Через этот прошивальщик (Modbus/RS-485) обновить бутлоадер нельзя.** Протокол бутлоадера (регистры 0x1000, 0x2000) предназначен только для записи **приложения** в область 0x0800800…0x08037FFF. Код бутлоадера находится в 0x08000000 (векторы) и 0x08038000 (32 КБ); устройство работает из бутлоадера, поэтому перезаписать его по Modbus изнутри невозможно.

**Как обновить бутлоадер:**

1. **ST-Link (или аналог)** — подключить программатор к отладочному разъёму устройства.
2. Собрать образ бутлоадера:  
   `make -C bootloader -j`  
   Результат: `bootloader/build/mp-02m_bootloader.elf` (или .hex с обоими регионами).
3. Записать образ через STM32CubeProgrammer / OpenOCD / `st-flash`:  
   - по одному ELF/HEX программатор сам прошивает оба региона (0x08000000 и 0x08038000);  
   - либо два .bin: `mp-02m_bootloader_0x08000000.bin` → 0x08000000, `mp-02m_bootloader_0x08038000.bin` → 0x08038000.
4. После обновления бутлоадера приложение (0x0800800) можно снова обновлять через этот прошивальщик по Modbus.

Подробнее: **`doc/BOOTLOADER_INTEGRATION.md`** (разделы 2.4, 3, 6).

## Если бутлоадер пишет «app invalid» (SP=0xFFFFFFFF)

Значит по адресу 0x08000800 пустая Flash (стерто, но приложение не записано или запись не прошла). Устройство остаётся в режиме бутлоадера. Нужно снова прошить **приложение**, собранное как **AppBoot** (`make AppBoot`, линкер `STM32F030CCXX_FLASH_boot.ld`), и использовать полученный .fw/.elf/.bin в прошивальщике.

## Если устройство не находится

Бутлоадер на **115200 8N1**, адрес Modbus всегда **247**. Сканирование перебирает адреса 1–247 и скорости 115200, 9600, 19200, 38400. Полный чек-лист: **`doc/BOOTLOADER_INTEGRATION.md`**, пункт **10** («Прошивальщик не находит устройство»).

## Сборка в .exe (PyInstaller)

Из **корня проекта**:

```bash
pip install pyinstaller
python flasher_windows/build_exe.py
```

Или вручную:

```bash
pyinstaller flasher_windows/MR-02m-Flasher.spec
```

Результат: **`dist/MR-02m-Flasher.exe`** — один файл, без консоли. Файл прошивки `MR-02m_<версия>.elf` или `.bin` положите в папку **`dist/`** рядом с exe (или в любую папку, где лежит exe при распространении).
