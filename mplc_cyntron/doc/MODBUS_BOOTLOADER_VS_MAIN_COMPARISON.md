# Сравнение реализации Modbus RTU: бутлоадер и основной проект

## 1. Обзор архитектуры

| Аспект | Основной проект | Бутлоадер |
|--------|-----------------|-----------|
| Стек | nanoMODBUS + modbus_rtu_hw.c | Собственная минимальная реализация (modbus_bl.c) |
| Режим | MODBUS_MODE_IRQ или MODBUS_MODE_DMA | Синхронный опрос (main loop + HAL_UART_Receive по 1 байту) |
| UART | USART2, PA1=DE, PA2/PA3 TX/RX | USART2, PA1=DE, PA2/PA3 TX/RX (тот же) |

## 2. Формат кадра и CRC

### 2.1 CRC16 Modbus

- **Стандарт:** полином 0xA001, начальное значение 0xFFFF, по проводу **LSB первым** (сначала младший байт CRC).

**Основной проект (nanomodbus.c):**
```c
uint16_t nmbs_crc_calc(const uint8_t* data, uint32_t length, void* arg) {
    uint16_t crc = 0xFFFF;
    for (uint32_t i = 0; i < length; i++) {
        crc ^= (uint16_t) data[i];
        for (int j = 8; j != 0; j--) {
            if ((crc & 0x0001) != 0) { crc >>= 1; crc ^= 0xA001; }
            else crc >>= 1;
        }
    }
    return (uint16_t) (crc << 8) | (uint16_t) (crc >> 8);  /* возврат с переставленными байтами */
}
```
- В буфер CRC пишется через `put_2(nmbs, crc)` → сначала старший байт 16‑битного значения, потом младший. Поскольку `crc` уже возвращён в порядке «LSB|MSB» в одном 16‑битном слове, в кадре получается **LSB, затем MSB** — корректно.

**Бутлоадер (modbus_bl.c):**
```c
buf[len]     = (uint8_t)(crc & 0xFF);   /* LSB */
buf[len + 1] = (uint8_t)(crc >> 8);     /* MSB */
```
- Порядок по проводу **LSB, MSB** — совпадает с основным проектом и стандартом.

**Вывод:** расчёт CRC и порядок байт в кадре в бутлоадере и в основном проекте согласованы.

### 2.2 Ответ Read Holding Registers (0x03)

Формат по стандарту: `[адрес 1B][0x03 1B][byte_count 1B][данные N×2B][CRC 2B]`, данные регистров — **старший байт регистра первым** (big-endian по регистру).

**Основной проект (handle_read_registers):**
- `put_res_header(nmbs, 1 + regs_bytes)` → пишет unit_id, fc (0x03);
- `put_1(nmbs, regs_bytes)` → byte_count;
- цикл `put_2(nmbs, regs[i])` → каждый регистр как (hi, lo).

**Бутлоадер (build_read_registers_response):**
- out[0]=slave, out[1]=resp_func, out[2]=byte_count;
- данные копируются из `reg_data[]` (уже в формате [hi,lo] на регистр);
- append_crc() — LSB, MSB.

**Вывод:** структура ответа 0x03 в бутлоадере совпадает с основным проектом и стандартом.

## 3. Приём кадра

### 3.1 Конец кадра (3.5 символа тишины)

**Основной проект:**
- **DMA:** `HAL_UARTEx_ReceiveToIdle_DMA` + таймаут приёмника (usart.c: 3.5 символа для &lt;19200, 1.75 ms для ≥19200).
- **IRQ:** приём по 1 байту в прерывании, таймер для 3.5 символа (fast_mb_port.c: Normal_Period, compute_timer).

**Бутлоадер (после правок):**
- `uart_bl_receive_frame`: по одному байту `HAL_UART_Receive(..., 1, inter_char_timeout_ms)`. Таймаут в main.c считается как **3.5 символа** (11 бит при 8N1) по текущей скорости: `3.5 * 11 * 1000 / baudrate_bps` мс, минимум 2 ms — как в основном проекте.

### 3.2 Проверка CRC и длины запроса

**Основной проект:** nanoMODBUS разбирает PDU, затем `recv_msg_footer` — приём 2 байт CRC и сравнение через `get_2` с переставленными байтами (см. выше).

**Бутлоадер:** для 0x03/0x04 считается ожидаемая длина кадра (8 байт для запроса), CRC считается по `frame_len-2` байт, сравнивается с `rx_buf[frame_len-2]`, `rx_buf[frame_len-1]`. Лишние байты (например 9‑й при 8‑байтном запросе) в CRC не входят — корректно.

## 4. Отправка ответа (RS‑485 DE и тайминг)

### 4.1 Основной проект

**DMA (modbus_rtu_hw.c):**
- Перед TX: `SetRS485Transmit()`, затем задержка **~10 циклов** (volatile loop), затем `HAL_UART_Transmit_DMA`.
- После TX: в `HAL_UART_TxCpltCallback` — задержка **~10 циклов**, затем `MB_RecieveFrame()` → `SetRS485Receive()`.
- Ожидание **полного выхода последнего байта (флаг TC)** не выполняется; переключение в RX сразу после завершения DMA (последний байт может ещё быть в сдвиговом регистре).

**IRQ (fast_mb_port.c write_serial):**
- Перед TX: `SetRS485Transmit()` без задержки, затем `HAL_UART_Transmit_IT`.
- Переключение в RX — в обработчике завершения передачи (UART_TxCplt → nano_RecieveMode / fastmodbus_RecieveMode).

### 4.2 Бутлоадер (uart_bl.c) — после правок

- Перед TX: **HAL_Delay(1)** (1 ms), затем `de_high()`, затем **HAL_Delay(1)** (стабилизация DE), затем `HAL_UART_Transmit` — как в основном проекте, минимальная задержка.
- После TX: **ожидание флага TC** (USART_ISR_TC), затем `de_low()` — строже, чем в основном проекте (DMA без TC).
- Затем сброс приёмника (чтение RDR при RXNE до 5 ms), чтобы эхо своего ответа не вошло в следующий кадр.

**Тайминг приведён к основному проекту:** задержка перед ответом уменьшена до 1 ms + 1 ms после DE; межсимвольный таймаут при приёме считается по скорости (3.5 символа), как в основном проекте.

## 6. Внесённые изменения в бутлоадер

1. **Задержка перед ответом** уменьшена до 1 ms + 1 ms после DE (uart_bl.c) — ответ укладывается в таймаут сканера, как в основном проекте.
2. **Межсимвольный таймаут при приёме** считается по скорости: 3.5 × 11 бит / baudrate (main.c), минимум 2 ms — как в основном проекте (usart.c / таймер IRQ).
3. Ожидание **TC** перед сбросом DE и сброс приёмника после TX оставлены — надёжнее, чем в основном проекте (DMA без TC).
