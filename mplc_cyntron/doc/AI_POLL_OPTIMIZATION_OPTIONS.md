# Варианты оптимизации быстродействия опроса аналоговых датчиков (12АИ и 6АО6АИ)

Документ подготовлен по анализу структуры проекта, кода и алгоритмов опроса AI для модулей **12АИ** и **6АО6АИ**.

---

## 1. Текущая временная модель одного канала

### 1.1 Один слот (один преобразование: 0–10 V, 4–20 mA, Disabled)

| Этап | Время | Где задаётся |
|------|------|-------------|
| FIRST_MUX_SET | ~0 ms | ai_channel_start → adc_worker_start → mux_setup + load_mux_mcp + ads1220_setup |
| load_mux_mcp | **≈7–12 ms** | adc_worker_task_c.c: HAL_Delay(2), (1), 1, verify×2 + WaitForReleaseSPI, 3 ms в конце. Для 12AI ch4–6: +2+1+1 ms по CS3 |
| FIRST_MUX_SET_WAIT | **55 ms** | MUX_SETTLE_TIME_MS (app_c.h) |
| Первое преобразование ADS1220 | **~22 ms** | 45 SPS (ads1220_c.c: ADS1220_DR_45_SPS) |
| **Итого один слот (single)** | **~84–89 ms** | |

### 1.2 Два преобразования (резисторы NTC/PT, термопара TXA)

| Этап | Время |
|------|--------|
| load_mux_mcp (1-й) | ~7–12 ms |
| FIRST_MUX_SET_WAIT | 55 ms |
| Первое преобразование | ~22 ms |
| adc_worker_second_start: mux_setup + load_mux_mcp (2-й) | ~7–12 ms (MUX **не меняется** — только конфиг АЦП) |
| SECOND_MUX_SET_WAIT | **55 ms** |
| Второе преобразование | ~22 ms |
| **Итого один слот (double)** | **~178–183 ms** |

### 1.3 Оценка полного цикла

- **12АИ:** 6 каналов × 2 слота (P+N) = 12 слотов. При смеси single/double в среднем порядка **1.5–2.5 s** на цикл (зависит от типов датчиков).
- **6АО6АИ:** 3 канала × 2 слота = 6 слотов → примерно **0.8–1.2 s** на цикл.

Отключённые слоты уже пропускаются (round-robin в `app_update_input`), что сокращает время при частично занятой конфигурации.

## 2. Варианты оптимизации

### 2.1 Сокращение времени установки MUX (MUX_SETTLE_TIME_MS) ✅ Применён

**Суть:** Уменьшить константу `MUX_SETTLE_TIME_MS` (было 55 ms в `Core/apps/inc/app_c.h` и `Core/Inc/app_c.h`). **Установлено 40 ms.**

**Рекомендации:**

- Сначала проверить работу при **45 ms** или **40 ms** на всех каналах (в т.ч. 4–6 для 12АИ). При стабильных показаниях — оставить уменьшенное значение.
- В документации (ANALOG_MEASUREMENTS_ALGORITHMS_AND_MUX.md) указано, что 55 ms взято из референса stm32mp02; при нестабильности ch4–6 можно, наоборот, поднять до 80–150 ms.

**Эффект:** Сокращение на **10–15 ms × число переходов MUX** за цикл (для double это два ожидания на слот). Для 12 слотов с double: до **~240 ms** выигрыша при 40 ms вместо 55 ms.

**Файлы:** `Core/apps/inc/app_c.h`, `Core/Inc/app_c.h`:

```c
#define MUX_SETTLE_TIME_MS       40   /* было 55; уменьшено для ускорения опроса */
```

---

### 2.2 Раздельное время ожидания для второго измерения (SECOND_MUX_SET_WAIT) ✅ Применён

**Суть:** При втором измерении (NTC/PT/TXA) **внешний MUX (MCP)** не меняется — те же `ext1_porta`, `ext1_portb`, `ext2_porta`. Меняется только конфигурация ADS1220 (внутренний MUX, gain, ref и т.д.). Полные 55 ms для «установки MUX» избыточны.

**Рекомендации:**

- Ввести отдельную константу, например `MUX_SETTLE_SECOND_MS` (10–20 ms), и использовать её только в режиме `APP_ADC_MODE_SECOND_MUX_SET_WAIT`.
- Альтернатива: использовать `MUX_SETTLE_TIME_MS` для первого переключения и уменьшенное значение (15–20 ms) для второго.

**Эффект:** Экономия **~35–40 ms на каждый слот с двойным преобразованием**. Для 6 таких слотов — около **210–240 ms** за цикл 12АИ.

**Изменения:**

- В `app_c.h`: добавить `#define MUX_SETTLE_SECOND_MS 18`.
- В `app_c.c` в ветке `APP_ADC_MODE_SECOND_MUX_SET_WAIT`: сравнивать `elapsed` с `MUX_SETTLE_SECOND_MS` вместо `MUX_SETTLE_TIME_MS`.

---

### 2.3 Сокращение задержек в adc_worker_load_mux_mcp()

**Суть:** В `adc_worker_task_c.c` используются фиксированные задержки:

- Для 12AI ch4–6: `HAL_Delay(2)`, `HAL_Delay(1)` при двойной записи 0x90 в CS3, затем `HAL_Delay(1)` после записи CS3, в конце функции — `HAL_Delay(3)`.

**Рекомендации:**

- Поочерёдно уменьшать задержки (например 2→1, 1→0, 3→2 ms) с проверкой стабильности каналов 4–6 (резисторы/термопары). При появлении выбросов или отрицательных r1 — вернуть предыдущие значения.
- Итоговый минимум по документу: «2+1+1+3 ms» уже был уменьшен с «5+3+2+10»; дальнейшее снижение возможно только экспериментально.

**Эффект:** Потенциально **2–5 ms на вызов load_mux_mcp**. При 12–18 вызовах за цикл — до **~60 ms** за цикл.

---

### 2.4 Ускорение ADS1220 (data rate)

**Суть:** Сейчас в `ads1220_set_config_1()` жёстко задано **45 SPS** (`ADS1220_DR_45_SPS`). В даташите ADS1220 есть режимы 90, 180 SPS и выше — время одного преобразования уменьшается (~11 ms при 90 SPS).

**Рекомендации:**

- Добавить в `ads1220_config_t` поле `data_rate` (или использовать существующий enum по битам DR) и задавать его из конфигов каналов. По умолчанию оставить 45 SPS.
- Для каналов, где допустим больший шум (например 0–10 V, 4–20 mA), можно задать 90 SPS; для термопар/резисторов оставить 45 SPS до проверки качества.
- Реализация: в `ads1220_c.c` в `ads1220_set_config_1()` подставлять значение из `config->data_rate` вместо константы `ADS1220_DR_45_SPS`.

**Эффект:** При 90 SPS время одного преобразования ~11 ms вместо ~22 ms — экономия **~11 ms на преобразование**. Для цикла с 12 слотами double (24 преобразования) — до **~264 ms**.

**Риск:** Возможное увеличение шума; нужно проверять точность и стабильность по типам датчиков.

---

### 2.5 Ослабление верификации MCP (verify_mcp_write)

**Суть:** В `adc_worker_task_c.c` после каждой записи в MCP выполняется read-back и при несовпадении — повтор с `HAL_Delay(1)` и вторая попытка. Для CS3 в 12AI при несовпадении ошибка не выставляется (считается успехом), но задержка и лишние обмены по SPI остаются.

**Рекомендации:**

- Для CS3 (12AI) можно не делать повтор при несовпадении (уже не выставляется ошибка), но убрать `HAL_Delay(1)` при ретрае или не вызывать ретрай вообще — сэкономить 1–2 ms и лишние обмены в редких случаях.
- Для CS2: оставить верификацию для надёжности; при желании уменьшить ретрай-задержку с 1 ms до 0 (только вторая попытка чтения без задержки).

**Эффект:** Небольшой — в основном при сбоях read-back; в норме один лишний обмен по SPI и до 1 ms на редкий ретрай.

---

### 2.6 Реже перезаписывать DAC в 6АО6АИ (ao6ai6_update)

**Суть:** В `module_ao6ai6.c` в `ao6ai6_update()` после `call_app_adc_worker(AO6AI6)` выполняются 6 вызовов `dac_write_with_retry()` — полная перезапись ЦАП при каждом обновлении модуля (каждый шаг автомата AI).

**Рекомендации:**

- Выполнять полную перезапись DAC не каждый вызов `ao6ai6_update`, а, например, раз в N вызовов (раз в полный цикл по всем слотам) или по таймеру (раз в 100–200 ms). Либо перезаписывать только при изменении `dac_registers` (сравнивать с закэшированными значениями).
- Это не ускоряет сам опрос АИ, но снижает нагрузку на SPI и блокировки во время опроса AI.

**Эффект:** Меньше задержек от DAC при каждом шаге автомата; субъективно «быстрее» отклик и меньше конфликтов по SPI.

---

### 2.7 Приоритет опроса «быстрых» слотов (опционально) ✅ Применён

**Суть:** Слоты с одним преобразованием (0–10 V, 4–20 mA) дают результат за ~84 ms, с двумя — за ~178 ms. Реализовано: сначала опрашиваются все слоты single, затем все double (`poll_single_phase` в `app_handle_t`, фаза переключается после исчерпания слотов текущего типа).

**Рекомендации:**

- Вариант: вести два списка слотов — «single» и «double» — и опрашивать сначала все single, затем все double (или наоборот). Тогда за первый проход по single пользователь быстрее получит обновление по напряжению/току. Реализация сложнее (нужно разделять индексы и порядок обхода).
- Альтернатива: оставить текущий порядок, но учитывать эту разницу при настройке ожидаемого времени обновления в верхнем уровне.

**Эффект:** Не сокращает суммарное время цикла, но улучшает воспринимаемую отзывчивость для каналов 0–10 V / 4–20 mA.

---

### 2.8 Таймаут ожидания АЦП (TIME_OUT_AI)

**Суть:** В `main.h` задано `TIME_OUT_AI (300)` ms. При зависании DRDY после 300 ms выполняется реинициализация ADS1220 и переход к следующему слоту.

**Рекомендации:**

- При переходе на 90 SPS время одного преобразования ~11 ms; таймаут 300 ms избыточен. Можно уменьшить до 150–200 ms, чтобы быстрее восстанавливаться после сбоев, не урезая нормальный цикл.

**Эффект:** Только при сбоях; на нормальный опрос не влияет.

## 4. Предлагаемый порядок внедрения

1. **Без риска:** ввести `MUX_SETTLE_SECOND_MS` и использовать его во втором ожидании (п. 2.2). Проверить все типы датчиков на 12АИ и 6АО6АИ.
2. **Низкий риск:** уменьшить `MUX_SETTLE_TIME_MS` до 45 ms (п. 2.1), затем при успехе — до 40 ms. Контроль каналов 4–6 (12АИ).
3. **По желанию:** сократить задержки в `adc_worker_load_mux_mcp()` (п. 2.3) пошагово с проверкой.
4. **Опционально:** добавить data rate в конфиг ADS1220 и перевести часть каналов на 90 SPS (п. 2.4) с проверкой качества.
5. Остальные пункты — по необходимости (DAC, verify, таймаут, приоритет слотов).

Ожидаемое суммарное сокращение времени полного цикла 12АИ при внедрении п. 2.1 и 2.2 — **порядка 400–500 ms** при сохранении стабильности измерений.
