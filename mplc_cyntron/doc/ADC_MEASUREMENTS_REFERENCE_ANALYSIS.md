# Анализ работы АЦП и измерений: МР-02м_12xAI и wiren-plc-release-v1.0

Документ суммирует код и комментарии, касающиеся работы АЦП и измерений в двух проектах-референсах, в сравнении с текущей реализацией в MP-02m.

---

## 1. МР-02м_12xAI (папка `МР-02м_12xAI`)

### Архитектура
- **АЦП:** встроенный ADC1 STM32F0 (один канал PA0), 12 бит. Нет внешнего ADS1220/ADS1120.
- **MCP23S17:** один чип по SPI (OLATA — выходы, OLATB/GPIOB — входы с подтяжкой). Используется для управления выходами и чтения кнопки.
- **Измерения:** в текущем `main.c` массив `Temperature[1..4]` отдаётся в Modbus, но **нигде не заполняется**. В Backup `main.c.bak` закомментированы вызовы:
  - `PT100_3950_2WIRE_P(1)`, `NTC10K_3950_2WIRE_N(5)`, `Current_20mA_P(1)`, `Voltage_10V_P(1)`, `PT1000_3950_2WIRE_P(1)` и т.д.
- В `main.c` также закомментированы строки чтения регистров ADS1120 — видимо, планировался переход на внешний АЦП, но не реализован.

### Вывод по МР-02м_12xAI
- Реализация измерений по каналам 1–6 (P/N) с PT100/NTC/ток/напряжение **отсутствует**: нет ни цикла переключения MUX, ни работы с ADS1220/ADS1120, ни расчёта сопротивления/температуры.
- Проект полезен только как справка по инициализации MCP23S17 (IODIRA, OLATA, IODIRB, GPPUB) и зарезервированным именам типов измерений (P/N, номера каналов).

## 2. wiren-plc-release-v1.0

### 2.1 АЦП (ADS1220)
- **Файлы:** `Core/periph/adc/ADS1220.hpp`, `ADS1220.cpp`.
- **Комментарий в коде (ADS1220.cpp):**  
  `// Every write access to any configuration register also starts a conversion!`  
  То есть запись в конфигурационные регистры может запускать преобразование — как и в нашем проекте и в stm32mp02.
- **Результат:** 24-бит знаковый: `int32_t r = ((int8_t)buf[0] << 16) | buf[1] << 8 | buf[2];` (три байта, в отличие от ADS1120).
- **Single conversion:** в комментарии указано ~50 ms на одно преобразование.
- **Типовой цикл одного измерения** (`single_task.cpp`):
  1. `mux_.setup(config.mux_config, config.ch, config.is_pos);`
  2. `adc_.setup(config.adc_config);`
  3. `HAL_Delay(5);`  — **только 5 ms** после установки MUX и конфига АЦП.
  4. `adc_.start();`
- Явного «отбрасывания» первого преобразования после `setup()` нет: после 5 ms вызывается `start()`, результат приходит по DRDY. То есть выдержка между переключением MUX и полезным преобразованием в wiren-plc — **5 ms** (против 75 ms в MP-02m и 55 ms в stm32mp02).

### 2.2 MUX
- **Реализация:** GPIO (MUX_A0, MUX_A1, MUX_DB, MUX1_EN…MUX4_EN), не MCP23S17. Файлы `mux.cpp`, `mux.hpp`.
- **Комментарии в mux.cpp:**
  - «P_IN1 --> MUX_DB (с помощью adc_sw можно подключить к REFP0)», «P_IN2 --> AIN1».
  - Для каналов 1–6 описан выбор позитивного/негативного входа (MUX1…MUX4, select_ch_pos/select_ch_neg).
- Логика выбора канала и полярности (P/N) согласована с конфигами ADC (Mux::MUX_1_AVSS, MUX_0_3 и т.д.) в `device_channel_p.cpp` / `device_channel_n.cpp`.

### 2.3 Два преобразования (double_task)
- **Файлы:** `double_task.cpp`, `double_task.hpp`.
- Последовательность: запуск первого измерения (config1) → по DRDY вызывается `on_task1` → сохраняется `task1_result_`, затем запускается второе измерение (config2) → по DRDY `on_task2` → вызывается общий callback с (res1, config1, res2, config2).
- Между первым и вторым измерением **нет дополнительной задержки**: сразу после получения первого результата стартует второй замер с новым MUX и конфигом АЦП. Выдержка перед каждым преобразованием — только те же 5 ms внутри `single_task::start()`.

### 2.4 Расчёт базовой величины (convert_to_base)
- **Файл:** `Core/device_channel.cpp`.
- **Сопротивление (PT100, PT1000, NTC10K, dry_contact):**  
  `return (1000LL * 100 * res1 * GAIN2 / GAIN1) / res2;`  
  — та же формула, что в stm32mp02 и в нашем проекте (база в 0.01 Ом). Обработки `res1 < 0` нет.
- **resistance_single:**  
  `return (res1 * (3300LL + 5000LL) * 100LL) / (ADS_T::RANGE_UINT - res1);`  
  с комментарием `// does not work` — в референсе не используется как рабочий вариант.
- Комментарии в `device_channel.hpp`: «Конфигурация MUX + ADC для первого замера», «для второго замера», «сырые отсчеты АЦП», «базовые физические величины… сотые доли Ома».

### 2.5 Документация и схемы
- В `doc/` есть `ads1220.pdf`, `ADS1120.pdf`, а также схемы: `Напряжение.png`, `Сопротивление_вар1.png`, `Сопротивление_вар2.png`, `Термопара.png` — полезны для проверки назначения выводов и схемы измерений.

## 3. Сравнение с текущим проектом MP-02m

| Аспект | МР-02м_12xAI | wiren-plc-release-v1.0 | stm32mp02 | MP-02m (наш) |
|--------|----------------|--------------------------|-----------|---------------|
| Внешний АЦП | Нет (закомментирован ADS1120) | ADS1220 | ADS1220 | ADS1220 |
| MUX | 1× MCP23S17 (GPIO) | GPIO (MUX_A0/A1, MUXx_EN) | MCP23S17 CS2/CS3 | MCP23S17 CS2/CS3 |
| Задержка после MUX/setup перед start | — | **5 ms** | 55 ms (MUX_WAIT_TIME) | 75 ms (MUX_SETTLE_TIME_MS) + 2 ms после load_mux_mcp |
| Отбрасывание 1-го преобразования | — | Нет (только 5 ms) | Да (ожидание DRDY, затем start) | Да (ожидание DRDY, затем start) |
| Формула R (0.01 Ом) | Нет кода | res1*100*GAIN2/GAIN1/res2 | То же | То же + обработка res1<0, переполнение в int64 |
| Два замера подряд | — | Подряд, без доп. задержки | С выдержкой MUX между замерами | С выдержкой MUX_SETTLE_TIME_MS |

## 4. Рекомендации для MP-02m

1. **Задержка после MUX:** В wiren-plc достаточно 5 ms; в stm32mp02 — 55 ms. У нас 75 ms может быть избыточной; при необходимости можно уменьшить `MUX_SETTLE_TIME_MS` (например до 55 ms) для ускорения цикла, если измерения стабильны.
2. **Формула сопротивления:** Совпадает с wiren-plc и stm32mp02; в нашем проекте добавлены защита от переполнения (int64, ограничение INT_MAX) и ветка при `res1 < 0` для устойчивости к сбоям/полярности.
3. **МР-02м_12xAI** для логики измерений с ADS1220 и MUX не используется — там нет ни цикла каналов, ни расчёта по двум отсчётам.
4. **wiren-plc** полезен как референс: порядок MUX → setup ADC → короткая задержка → start, конфиги MUX/ADC по каналам (device_channel_p/n), формула сопротивления и комментарии к схеме (doc/).
