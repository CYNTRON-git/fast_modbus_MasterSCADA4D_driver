# Техническое задание: приложение для Windows — обновление прошивки устройств MP-02m (MR-02m)

**Версия:** 1.0  
**Дата:** 2025-02-08  
**Основа:** протокол и требования из `doc/BOOTLOADER_TZ.md` (бутлоадер MP-02m, протокол обновления по Modbus).

---

## 1. Назначение и область применения

- **Назначение:** настольное приложение для ОС **Windows**, предназначенное для обновления прошивки устройств **MP-02m (MR-02m)** по интерфейсу RS-485 (Modbus RTU) через COM-порт или USB‑RS485 преобразователь.
- **Целевое устройство:** MP-02m с бутлоадером, совместимым с протоколом обновления по Modbus (см. `BOOTLOADER_TZ.md`).
- **Файл прошивки:** располагается в **корневой папке приложения** (папка, в которой находится исполняемый файл программы). Имя файла: **`MR-02m_<версия>.elf`** или **`MR-02m_<версия>.bin`**, где `<версия>` — версия прошивки в формате четырёх чисел, разделённых точкой, например **`1.3.5.2`**. Пример полного имени: **`MR-02m_1.3.5.2.elf`** или **`MR-02m_1.3.5.2.bin`**.

---

## 2. Ссылки и зависимости

- **Протокол обновления и регистры:** `doc/BOOTLOADER_TZ.md` (разделы 5–6, 10).
- **Формат прошивки на устройстве:** образ приложения с адреса **0x0800800** (см. BOOTLOADER_TZ, п. 4.1, 10). Из .elf используется образ, загружаемый по адресу 0x0800800 (сегменты .text/.data и т.д. для этого адреса).

---

## 3. Требования к файлу прошивки

### 3.1 Расположение и имя

- Файл прошивки лежит в **корневой папке приложения** (текущая рабочая директория при запуске или директория исполняемого файла — на усмотрение реализации, но единообразно).
- Допустимые имена:
  - **`MR-02m_<X>.<Y>.<Z>.<W>.elf`** — образ в формате ELF (например `MR-02m_1.3.5.2.elf`).
  - **`MR-02m_<X>.<Y>.<Z>.<W>.bin`** — сырой бинарный образ (уже собранный под адрес 0x0800800).
- Версия из имени файла (X.Y.Z.W) должна отображаться в интерфейсе и, при необходимости, использоваться для подписи или лога.

### 3.2 Обработка форматов

- **.bin:** считать файл как непрерывный образ прошивки для записи с адреса 0x0800800; размер образа = размер файла.
- **.elf:** извлечь образ для загрузки по адресу **0x0800800**: выбрать загружаемые сегменты (loadable segments), относящиеся к диапазону 0x0800800 и выше; сформировать непрерывный бинарный образ с выравниванием по необходимости (пробелы заполнить 0xFF или по спецификации ELF). Размер образа = суммарный размер извлечённых данных до конца последнего сегмента в области приложения. Инструменты: парсинг ELF вручную или использование библиотеки (например libelf, elftoolchain) / утилиты (objcopy) — на усмотрение реализации.

### 3.3 Проверки перед прошивкой

- Файл существует и доступен для чтения.
- Для .elf: наличие загружаемого кода по адресу 0x0800800 (или явная ошибка «нет подходящего образа»).
- Размер образа не превышает допустимый для области приложения (например 238 КБ для текущего линкера приложения); при превышении — предупреждение или отказ с сообщением.

## 4. Протокол обновления (кратко)

Соответствие `BOOTLOADER_TZ.md`, разделы 5–6.

- **Параметры связи с бутлоадером:** по умолчанию **115200 8N1**. Адрес Modbus в режиме бутлоадера всегда **247**.
- **Переход в бутлоадер:** запись значения **1** в **holding-регистр 129** (0x81). После этого устройство перезагружается и входит в режим бутлоадера на **120 с**.
- **Info-блок (BEGIN):** запись **16 регистров** (32 байта) по адресу **0x1000** (Modbus Write Multiple Registers, функция 0x10). Содержимое:
  - байты 0–11: **сигнатура устройства** (12 байт ASCII, дополненная нулями справа при необходимости);
  - байты 12–15: **размер прошивки в байтах** (32-битное целое, порядок байт — **little-endian**);
  - байты 16–31: резерв (нули).
- **Блоки данных (DATA):** запись по адресу **0x2000** (функция 0x10). **Приложение:** 68 регистров (136 байт) на блок; образ разбивается на блоки по 136 байт. **Образ бутлоадера:** 128 регистров (256 байт) на блок, 136 блоков. В кадре Modbus слова — **big-endian**. Последний блок приложения может быть короче (дополняется нулями).
- **Сигнатура устройства:** должна совпадать с сигнатурой, записанной в EEPROM устройства (см. BOOTLOADER_TZ, п. 5.4). Для MP-02m использовать константу сигнатуры, зашитую в приложение (например **`mp02m`** или **`mr02m`** — 6 символов + 6 нулей до 12 байт), либо настраиваемую пользователем в пределах 12 символов ASCII.

## 5. Функциональные требования к приложению

### 5.1 Выбор порта и параметров

- Выбор **COM-порта** (список доступных портов Windows: `COM1`, `COM2`, …).
- **Скорость по умолчанию для прошивки:** 115200 (связь с бутлоадером после перехода по регистру 129). При сканировании и при работе с уже найденным устройством используются параметры, определённые при сканировании или настройки по умолчанию (115200 8N1, адрес 247 для бутлоадера).
- **Параметры кадра:** 8 бит данных; для бутлоадера — 8N1.

### 5.2 Сканирование линии (поиск устройств)

- **Кнопка «Сканировать»** (или «Найти устройства»): запуск сканирования линии на выбранном COM-порту.
- **Алгоритм сканирования:**
  1. **Шаг 1 — широковещательный опрос (адрес 0) с «быстрым» Modbus:** открыть порт на повышенной скорости (например 115200 8N2 или 9600 8N2 — на усмотрение реализации), отправить запрос на чтение регистров на **широковещательный адрес 0** (например чтение регистров 290, 12 шт. — сигнатура). Если на линии одно устройство в режиме бутлоадера, оно может ответить на broadcast. Таймаут ответа — короткий (например 100–300 мс). При получении корректного ответа зафиксировать устройство (адрес 0 или адрес из ответа, если протокол это позволяет; иначе считать «найдено одно устройство на 0»). Если ответа нет — перейти к шагу 2.
  2. **Шаг 2 — пошаговое сканирование Modbus RTU:** перебор адресов **1–247**. Для каждого адреса: попытка чтения регистров (например 290, 12 регистров — сигнатура в бутлоадере, или 320–321 — версия в приложении). Параметры порта: по умолчанию 115200 8N1; при необходимости перебирать скорости (115200, 9600, 19200, 38400 и т.д.). Бутлоадер всегда на адресе **247**, 115200 8N1. Таймаут на один адрес — короткий (100–300 мс).
- **Результат сканирования:** все найденные устройства заносятся в **таблицу устройств** (см. п. 5.3). Повторное сканирование очищает или обновляет таблицу (на усмотрение реализации: либо полная замена, либо обновление строк по адресу).

### 5.3 Таблица найденных устройств

- **Таблица** с колонками (минимальный набор):
  - **Адрес** — Modbus-адрес устройства (0–247).
  - **Скорость** — определённая при сканировании скорость (бит/с).
  - **Чётность** — N / E / O.
  - **Стоп-биты** — 1 или 2.
  - **Название модуля (сигнатура)** — строка из регистров 290 (12 регистров, по байту в регистре), в режиме бутлоадера; в режиме приложения можно оставить пусто или взять из доступных регистров идентификации.
  - **Версия прошивки** — версия основной программы (например из регистров 320–325 приложения: MAJOR.MINOR.PATCH.SUFFIX, см. MODBUS_VARIABLES.txt); в режиме бутлоадера до прошивки — «—» или предыдущая версия, если где-то сохранена.
  - **Версия бутлоадера** — строка из регистров 330 (8 регистров), читается в режиме бутлоадера; в режиме приложения — по возможности прочитать те же регистры, если приложение их проксирует, иначе «—».
  - **Серийный номер** — 32-битное значение (например из регистров 270–271 приложения или аналог в бутлоадере); отображать в hex или decimal (например `0x0E0A61A8` или десятичное).
- Допускается добавлять колонки: статус (в приложении / в бутлоадере), время последнего ответа и т.д.
- Выбор строки в таблице может подставлять адрес и параметры связи в поле «Устройство для обновления» и параметры порта (см. п. 5.4).

### 5.4 Выбор устройства для прошивки и кнопки обновления

- **Поле ввода «Устройство для обновления»:** пользователь задаёт либо **Modbus-адрес** (число 0–247), либо **серийный номер** устройства (в десятичном или шестнадцатеричном виде). При вводе серийного номера приложение находит в таблице найденных устройств строку с совпадающим серийным номером и использует адрес и параметры связи этого устройства для прошивки.
- **Кнопка «Обновить»** (или «Прошить»): обновление **одного** устройства — того, чей адрес или серийный номер указан в поле ввода. Если указан адрес — искать в таблице параметры связи; если адрес не найден (в т.ч. для бутлоадера), использовать по умолчанию **115200 8N1**, для бутлоадера адрес **247**.
- **Кнопка «Обновить все»:** последовательное обновление **всех** устройств из таблицы. Для каждого: переход в бутлоадер по регистру 129, пауза 2 с, переключение на **115200 8N1**, адрес **247** при прошивке образа бутлоадера, отправка info и блоков данных. Отображать прогресс по блокам. При ошибке — сообщение (адрес, причина), предложить пропустить или остановить.

### 5.5 Поиск файла прошивки

- При запуске или по кнопке «Обновить список» / «Найти прошивку» сканировать корневую папку приложения на наличие файлов **`MR-02m_*.elf`** и **`MR-02m_*.bin`**.
- Отображать найденные файлы с извлечённой версией (из имени), размером образа и путём. Допустимо показывать один «текущий» файл (например последний по дате изменения или выбранный пользователем).
- Если файлов несколько — пользователь выбирает нужный. Если ни одного — вывести сообщение «Файл прошивки не найден. Поместите MR-02m_<версия>.elf или .bin в папку программы».

### 5.6 Сценарий обновления

1. **Проверка файла:** наличие выбранного файла, корректность .elf/.bin, размер образа в допустимых пределах.
2. **Подготовка payload:** сформировать 32-байтный info-блок (сигнатура 12 байт + размер 4 байта LE + резерв) и разбить образ на блоки по 136 байт (последний блок дополнен нулями до 136 байт); каждый блок для Modbus — 68 регистров, слова в big-endian.
3. **Открытие порта:** открыть выбранный COM-порт. Параметры связи для команды перехода в бутлоадер: использовать параметры устройства из таблицы (если устройство было найдено при сканировании) — скорость, чётность, стоп-биты; иначе 9600 8N2.
4. **Переход в бутлоадер:** отправить запись в регистр 129 значение 1 (Modbus Write Single Register, функция 0x06) на адрес выбранного устройства. При таймауте или ошибке — сообщение «Не удалось перевести устройство в режим бутлоадера. Проверьте порт, адрес и питание.»; повторить попытку (например до 2–3 раз) или считать, что устройство уже в бутлоадере.
5. **Пауза:** подождать **2 с** после команды перехода (устройство перезагружается).
6. **Переключение на параметры бутлоадера (если нужно):** бутлоадер отвечает на **115200 8N1**, адрес **247**. После паузы переключить порт на эти параметры для отправки info и блоков данных.
7. **Отправка info-блока:** запись 16 регистров по адресу 0x1000. При ответе Slave Failure — сообщение «Несовпадение сигнатуры или устройство не в режиме бутлоадера»; завершить с ошибкой.
8. **Отправка блоков данных:** по адресу 0x2000: приложение — блоки по **68 регистров (136 байт)**; образ бутлоадера — блоки по **128 регистров (256 байт)**, 136 блоков. Отображать прогресс. При ошибке ответа — повтор (до 3 раз на блок); при повторной неудаче — прервать.
9. **Завершение:** после успешной отправки всех блоков вывести сообщение об успешной прошивке. Опционально: отправить запись в регистр **1004** (мгновенный переход в прошивку) и закрыть порт.
10. **Закрытие порта** во всех сценариях (успех, ошибка, отмена). При «Обновить все» порт может оставаться открытым между устройствами с переключением параметров и адреса.

### 5.7 Дополнительные функции (рекомендуется)

- **Чтение информации об устройстве в режиме бутлоадера:** перед началом прошивки (после паузы 2 с) прочитать регистры **290** (12 регистров — сигнатура) и **330** (8 регистров — версия бутлоадера), отобразить в окне (например «Сигнатура: …», «Версия бутлоадера: …»). Это помогает убедиться, что устройство в режиме бутлоадера и сигнатура совпадает.
- **Лог операций:** вывод в окно или файл лога шагов (открытие порта, переход в бутлоадер, отправка info, блоки, ошибки, таймауты).
- **Отмена:** кнопка «Отмена» во время отправки блоков; прервать отправку и закрыть порт.

## 7. Технические требования

### 7.1 Modbus RTU

- Реализация клиента Modbus RTU: функции **0x03** (Read Holding Registers), **0x06** (Write Single Register), **0x10** (Write Multiple Registers).
- Таймаут ответа ведомого: настраиваемый или фиксированный (например 2–5 с для операций записи, 1–2 с для чтения).
- Расчёт CRC16 (Modbus): полином 0xA001 (младший байт первым в кадре), начальное значение 0xFFFF.
- Порядок байт в кадре Modbus: адрес, код функции, данные, CRC (младший байт CRC, затем старший).

### 7.2 Формат данных для записи регистров

- **Info-блок (32 байта → 16 регистров):** в кадре 0x10 каждый регистр — 2 байта. Порядок байт в регистрах: **big-endian** (старший байт первого байта пары — в первом байте регистра). Сигнатура: байты 0–11 (6 регистров); размер прошивки (4 байта, little-endian) занимает байты 12–15 (2 регистра); резерв 16–31 (8 регистров).
- **Блок данных (136 байт → 68 регистров):** каждый регистр = 2 байта образа, порядок в кадре Modbus — **big-endian** (первый байт пары — старший).

### 7.3 Обработка ошибок и устойчивость

- Проверка открытия порта; сообщение, если порт занят или недоступен.
- Таймауты на все операции обмена; не зависать при отсутствии ответа устройства.
- Повторные попытки для записи блоков (например до 3 раз) с краткой паузой между попытками.
- Корректное закрытие порта при завершении (нормальном и по ошибке) и при закрытии окна приложения.

---

## 8. Сигнатура устройства

- В info-блоке передаётся **сигнатура устройства** (12 байт ASCII). Она должна совпадать с сигнатурой, записанной в EEPROM устройства (см. BOOTLOADER_TZ).
- В приложении задать **константу сигнатуры по умолчанию** для MP-02m / MR-02m (например **`mp02m`** или **`mr02m`**), дополненную нулями до 12 байт. Допустимо сделать сигнатуру настраиваемой (поле в настройках или в конфигурационном файле) в пределах 12 символов.

## 9. Критерии приёмки

1. При наличии в корневой папке приложения файла **`MR-02m_<версия>.elf`** или **`MR-02m_<версия>.bin`** (например `MR-02m_1.3.5.2.elf`) приложение обнаруживает его, извлекает версию из имени и отображает в интерфейсе.
2. Из .elf корректно извлекается образ для адреса 0x0800800; из .bin используется весь файл как образ. Размер образа отображается и проверяется на допустимость.
3. Кнопка **«Сканировать»** на выбранном COM-порту выполняет: сначала широковещательный опрос (адрес 0) с быстрым таймаутом; при отсутствии ответа — пошаговое сканирование адресов 1–247. Найденные устройства выводятся в таблицу с колонками: адрес, скорость, чётность, стоп-биты, название модуля (сигнатура), версия прошивки, версия бутлоадера, серийный номер.
4. В поле «Устройство для обновления» можно ввести **адрес** (0–247) или **серийный номер**; при вводе серийного номера для прошивки используется адрес и параметры связи из таблицы найденных устройств.
5. Кнопка **«Обновить»** прошивает одно устройство (по введённому адресу или серийному номеру). Последовательность: запись 1 в регистр 129 на параметрах устройства → пауза 2 с → при необходимости переключение на 9600 8N2 → запись info-блока (0x1000) → запись блоков данных (0x2000). Прогресс отображается.
6. Кнопка **«Обновить все»** последовательно прошивает все устройства из таблицы; порядок — по адресу или по порядку строк. Отображается прогресс по устройствам и по блокам; при ошибке на устройстве — сообщение с возможностью пропустить и продолжить или остановить.
7. При успешной отправке всех блоков выводится сообщение об успешном обновлении; устройство перезагружается и запускает новую прошивку.
8. При несовпадении сигнатуры устройство возвращает ошибку; приложение отображает понятное сообщение и не считает прошивку успешной.
9. Ошибки порта, таймауты и ошибки Modbus обрабатываются без падения приложения; выводятся сообщения в лог/статус.
10. Документация для пользователя: краткая инструкция (сканирование, выбор устройства по адресу/серийному номеру, файл прошивки, «Обновить» / «Обновить все») и описание формата имени файла и версии.
