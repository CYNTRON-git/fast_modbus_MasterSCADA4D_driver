# План формирования отладочной информации по типу модуля расширения

Отладочный вывод включается макросом `COM_PORT_DEBUG` и направляется на порт, заданный `PRINTF_UART`. Формат вывода должен быть единообразным и зависеть **только от типа модуля** (мезонина), определённого в `set_type_module()`.

---

## 1. Общая последовательность вывода (все модули)

1. **Фаза инициализации (один раз при старте)**  
   - Инициализация подсистем: HAL, GPIO, DMA, SPI, TIM, ADC, I2C.  
   - Результат определения типа модуля: `type`, имя модуля, код ошибки (если есть).  
   - EEPROM: результат инициализации, чтение конфигурации, CRC.  
   - Память/конфиг: адрес Modbus, скорость, серийный номер (если нужно в отладке).  
   - Инициализация устройств модуля (MCP23S17, ADS1220, ЦАП, MUX и т.д. — в зависимости от типа).  
   - Инициализация приложения (app_create и т.п.) при модулях с AI.

2. **Циклический вывод (по таймеру или по опросу)**  
   - Только то, что относится к выбранному типу модуля (см. разделы по модулям ниже).

---

## 2. Модуль 12AI (12 аналоговых входов)

**Инициализация:**  
- Режимы MCP23S17 (CS2, CS3): A_WRITE_B_READ_SPEC, проверка REG_BANK_0_IPOLB, режим A_WRITE_B_WRITE для CS3.  
- Инициализация ADS1220 (конфигурация, калибровка при наличии).  
- Инициализация MUX (маппинг каналов 1–6 P/N на входы ADS1220).  
- Инициализация каналов приложения: количество каналов (6), пары P/N.

**По каналам (для каждого канала 1–6, P и N):**  
- Номер канала, полярность (P/N).  
- Тип датчика (строка: NTC10K, PT1000, TXA, напряжение, ток и т.д.).  
- Сырое значение с АЦП: `r1`, при двух измерениях — `r2` (или эквивалент).  
- Пересчитанное значение: сопротивление (0.01 Ом), температура (0.1 °C), мкВ/мА в зависимости от типа датчика.  
- Итоговое значение для Modbus (например, десятые градуса или единицы по датчику).

Формат строки (пример):  
`[12AI] ch N P: sensor=NTC10K raw_r1=... raw_r2=... base_centiohm=... value_0.1C=...`

---

## 3. Модуль 6AO6AI (6 аналоговых выходов, 6 аналоговых входов)

**Инициализация:**  
- Аналогично 12AI по части AI: MCP23S17 (CS2, CS3), ADS1220, MUX.  
- Инициализация ЦАП (AD5324/AD53x4): проверка записи/чтения.  
- Инициализация каналов приложения: 6 AI (каналы 4–6 и 1–3 с P/N).

**По аналоговым входам:**  
- То же, что для 12AI: тип датчика, сырые r1/r2, пересчитанное значение, значение для Modbus.

**По аналоговым выходам (при изменении или по запросу):**  
- Номер выхода, заданное значение (регистр/напряжение или код ЦАП).

Формат (пример):  
`[6AO6AI] AI ch N P: sensor=... raw=... value=...`  
`[6AO6AI] AO out M: set=...`

---

## 4. Модуль DO6DI8 (6 дискретных выходов, 8 дискретных входов)

**Инициализация:**  
- MCP23S17: режимы портов (A/B Read/Write), проверка записи/чтения регистров.  
- Количество DO, DI.

**Циклически (при опросе или по изменению):**  
- Состояние DI: номера входов, текущие значения (0/1).  
- Состояние DO: номера выходов, текущие значения (0/1).

Формат (пример):  
`[DO6DI8] DI 1..8: ... DO 1..6: ...`

---

## 5. Модуль DO16 (16 дискретных выходов)

**Инициализация:**  
- MCP23S17 (или расширители): инициализация портов, проверка связи.  
- Количество выходов (16).

**Циклически:**  
- Состояние DO 1..16 (по изменению или по запросу).

---

## 6. Модуль AO12 (12 аналоговых выходов)

**Инициализация:**  
- ЦАП (AD53x4 и т.д.): инициализация, проверка записи.  
- Количество каналов (12).

**Циклически:**  
- Значения выходов (код ЦАП или напряжение) при изменении.

---

## 7. Модуль DO6 (6 дискретных выходов)

**Инициализация:**  
- MCP23S17 или иной драйвер: режимы портов, проверка.  
- Количество DO (6).

**Циклически:**  
- Состояние DO 1..6.

---

## 8. Модуль DI14 (14 дискретных входов)

**Инициализация:**  
- MCP23S17 (и при необходимости другие расширители): настройка входов, проверка чтения.  
- Количество DI (14).

**Циклически:**  
- Состояние DI 1..14.

---

## 9. Модуль DO4DI6 (4 дискретных выхода, 6 дискретных входов)

**Инициализация:**  
- MCP23S17: порты A/B для DO и DI, проверка.  
- Количество DO (4), DI (6).

**Циклически:**  
- DI 1..6, DO 1..4.

---

## 10. Модуль EN_METER (энергосчётчик)

**Инициализация:**  
- ATM90E32 (или иной чип): регистры, связь по SPI.  
- Наличие напряжения/тока по фазам.

**Циклически:**  
- Пиковые напряжения/токи по фазам A, B, C (или доступные величины).  
- Фазовые углы при необходимости.  
- Коды ошибок/статус счётчика при наличии.

---

## 11. Реализация

- В `main.c` (или единой точке входа отладки) после определения типа модуля вызывать функцию вида `debug_init_output(mp02_t type)`, которая один раз выводит блок инициализации для этого типа.  
- В цикле (таймер или `update_input`/обработчики модуля) вызывать `debug_poll_output(mp02_t type)` (или по типу вызывать модуль-специфичный вывод).  
- Все строки должны иметь префикс типа модуля, например `[12AI]`, `[6AO6AI]`, `[DO6DI8]`, чтобы при смешении логов можно было фильтровать по типу.  
- Уровни детализации (только ошибки / инициализация / плюс циклические данные по каналам) задавать через существующие флаги отладки (например `get_debug_poll_ai()`, `get_debug_poll_ai_verb()`) или новые, единые для всех модулей.

---

## 12. Удалённая отладка

- Весь старый разрозненный вывод (MP_DEBUG_PRINT, MP_AI_DEBUG_PRINT и т.д.) удалён или заменён на вызовы по данному плану.  
- Новый вывод добавлять только в выделенных функциях/файлах отладки (например `debug_output.c` / `debug_output.h`) с ветвлением по `get_type_module()`, без дублирования логики в рабочих модулях.
