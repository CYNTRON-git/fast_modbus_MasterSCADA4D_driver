# Соответствие реализации Modbus стандарту Modbus over serial line V1.02

Сверка с [Modbus over serial line specification V1.02](https://ftp.owen.ru/ModbusCourse/00_ModbusSpecs/Modbus_over_serial_line_V1_02.pdf) (Owen, Modbus.org).

---

## 1. Формат кадра RTU

| Требование стандарта | Реализация | Статус |
|----------------------|------------|--------|
| Кадр: [Slave Address][PDU][CRC16] | `modbus.c`: `recv_msg_header` — unit_id (1 байт), fc (1 байт), затем PDU по коду функции; `recv_msg_footer` — 2 байта CRC | ✅ Соответствует |
| Адрес 1 байт (1..247 для slave, 0 = broadcast) | `modbus_rtu_hw.c`: `get_modbusaddress()`, запись в рег. 128 только 1..247; `nmbs_server_create(&nmbs, get_modbusaddress(), ...)` | ✅ Соответствует |
| PDU: код функции + данные | Обработчики по FC в `modbus.c` и `modbus_rtu_hw.c` | ✅ Соответствует |
| CRC — 2 байта, после PDU | `recv_msg_footer`: приём 2 байт, сравнение с расчётом; `send_msg`: добавление CRC перед отправкой | ✅ Соответствует |

---

## 2. CRC-16 (Modbus)

| Требование стандарта | Реализация | Статус |
|----------------------|------------|--------|
| Полином 0xA001 (LSB-first), начальное значение 0xFFFF | `modbus.c`: `nmbs_crc_calc()` — init 0xFFFF, полином 0xA001 в цикле по битам | ✅ Соответствует |
| CRC передаётся в кадре в порядке: младший байт, старший байт | `nmbs_crc_calc` возвращает `(crc << 8) \| (crc >> 8)`; `put_2()` пишет MSB затем LSB от этого значения → на линии получается low, high | ✅ Соответствует |
| CRC считается по полю от Slave Address до конца PDU (без CRC) | `recv_msg_footer`: расчёт по `nmbs->msg.buf` длины `buf_idx`; при приёме CRC сравнивается с `get_2()` | ✅ Соответствует |

---

## 3. Порядок байт (данные в PDU)

| Требование стандарта | Реализация | Статус |
|----------------------|------------|--------|
| Многобайтовые значения (адреса, счётчики, регистры) — Big-endian (старший байт первым) | `get_2()`: `(buf[i]<<8)\|buf[i+1]`; `put_2()`: сначала `(data>>8)&0xFF`, затем `data&0xFF` | ✅ Соответствует |

---

## 4. Тайминги (T1.5 и T3.5)

| Требование стандарта | Реализация | Статус |
|----------------------|------------|--------|
| T3.5 — минимум 3.5 времени символа между кадрами (или эквивалент по линии) | **DMA:** `usart.c` — расчёт таймаута: при BaudRate ≥ 19200 — 1750 µs (115200: 2000 µs); при < 19200 — 3.5×bits_per_char/BaudRate; `HAL_UART_ReceiverTimeout_Config`; используется IDLE (конец приёма по паузе). **IRQ:** `tim.c` — таймер 3.5 символа (Normal_Period) от baudrate | ✅ Соответствует |
| При скорости ≥ 19200 допускается фиксированный T3.5 = 1.75 мс | `usart.c`: 1750 µs при 19200..<115200; 2000 µs при 115200 | ✅ Соответствует |
| T1.5 — между символами внутри кадра (как правило, обеспечивается непрерывностью передачи) | Обеспечивается мастером; слейв принимает поток и определяет конец кадра по T3.5/IDLE | ✅ Допустимо |

Примечание: в DMA-режиме конец кадра определяется по UART IDLE (Receiver Timeout), что эквивалентно требованию «тишина не менее T3.5» и допустимо по смыслу стандарта.

## 5. Физический уровень и параметры линии

| Требование стандарта | Реализация | Статус |
|----------------------|------------|--------|
| EIA-485 (RS-485), полудуплекс | `modbus_rtu_hw.c`: SetRS485Transmit/SetRS485Receive по GPIO (DE); перед/после передачи переключение направления | ✅ Соответствует |
| Скорость, чётность, стоп-биты — конфигурируемы | `i2c.c`/config: baudrate (например 9600, 19200, 38400, 57600, 115200), parity (0/1/2), stopbits (1/2); `usart.c`: применение к UART | ✅ Соответствует |
| Ошибки линии (PE, FE, NE, ORE) — не отвечать на запрос | `modbus_rtu_hw.c`: при IDLE проверка `huart->ErrorCode`; при ошибке — AbortReceive, сброс, перезапуск приёма, ответ не формируется | ✅ Соответствует |

## 6. Адрес broadcast (0)

| Требование стандарта | Реализация | Статус |
|----------------------|------------|--------|
| Запрос на адрес 0 — broadcast; на broadcast **не должно быть ответа** | В `modbus.c` в `recv_req_header`: при `unit_id == NMBS_BROADCAST_ADDRESS` (0) выставляется `unit_id = nmbs->address_rtu` и `broadcast = false`, затем выполняется обычная обработка и **формируется ответ** с адресом слейва (для поддержки сканирования шины). | ⚠️ Отклонение |

**Вывод:** по стандарту V1.02 на broadcast ответ не допускается. В проекте ответ на broadcast делается намеренно (ответ с реальным адресом для сканеров). Это осознанное расширение, а не ошибка; при необходимости строгого соответствия стандарту ответ на адрес 0 следует отключать (не вызывать отправку ответа при broadcast).

## 7. Коды функций (поддерживаемые)

| Код | Функция | Реализация | Статус |
|-----|---------|------------|--------|
| 0x01 | Read Coils | `handle_read_coils` в modbus_rtu_hw.c, callback в modbus.c | ✅ |
| 0x02 | Read Discrete Inputs | `handle_read_discrete_inputs` | ✅ |
| 0x03 | Read Holding Registers | `handler_read_holding_registers` → `read_input_holding` | ✅ |
| 0x04 | Read Input Registers | `handle_read_input_registers` | ✅ |
| 0x05 | Write Single Coil | `handle_write_single_coil` | ✅ |
| 0x06 | Write Single Register | `handle_write_single_register` | ✅ |
| 0x0F | Write Multiple Coils | `handle_write_multiple_coils` | ✅ |
| 0x10 | Write Multiple Registers | `handle_write_multiple_registers` | ✅ |

Формат PDU (адрес, количество, данные) и ограничения (например, до 125 регистров за один запрос) обрабатываются в библиотеке и в обработчиках.

## 8. Исключения (exception responses)

| Требование стандарта | Реализация | Статус |
|----------------------|------------|--------|
| Ответ при ошибке: [Slave Address][FC+0x80][Exception Code][CRC] | `send_exception_msg`: fc += 0x80, put_msg_header, put_1(exception), send_msg | ✅ Соответствует |
| Код исключения 1 байт (01..04 по стандарту) | NMBS_EXCEPTION_ILLEGAL_FUNCTION=1, ILLEGAL_DATA_ADDRESS=2, ILLEGAL_DATA_VALUE=3, SERVER_DEVICE_FAILURE=4; при приёме ответа проверка 1 ≤ exception ≤ 4 | ✅ Соответствует |

В прикладном коде возвращаются те же коды (например, при неверном адресе/значении в регистрах 110, 111, 112, 128 и т.д.).

---

## 9. Дополнительные замечания

- **Максимальная длина PDU:** стандарт — 256 байт; буфер `nmbs.msg.buf[260]` достаточен для RTU (адрес + PDU + CRC).
- **Адрес 0xFD:** пакеты с адресом 0xFD в `modbus_rtu_hw.c` не передаются в стандартный Modbus (обрабатываются только как «быстрый» Modbus), что не противоречит стандарту (адреса 248–255 зарезервированы).
- **Бутлоадер:** использует тот же стек (modbus.c) с отключёнными частью функций (только 0x03, 0x04, 0x10 и т.д.), формат кадра и CRC совпадают со стандартом.
