# Детальное описание алгоритмов измерения аналоговых сигналов и работы MUX

Документ составлен по даташиту ADS1220 (TI), коду проектов **MP-02m**, **stm32mp02** и **wiren-plc-release-v1.0**. Описываются пошаговые алгоритмы для каждого типа датчика, положение и назначение MUX, связи между конфигурацией АЦП и мультиплексором.

---

## 1. Краткие сведения по ADS1220 (даташит)

### 1.1 Назначение и возможности

- **ADS1220** — 24-битный АЦП с внутренним PGA, опорой, двумя программируемыми источниками тока (IDAC) и встроенным датчиком температуры.
- **Входы:** 4 single-ended / 2 differential (AIN0–AIN3). AINP/AINN выбираются через регистр конфигурации (MUX).
- **PGA:** усиление 1–128 (или bypass до 4 V/V). При bypass входное сопротивление высокое, диапазон по напряжению больше.
- **Режим:** Single-Shot или Continuous. В проектах используется Single-Shot; преобразование запускается командой START (0x08) или **при записи в регистр конфигурации** (важно для порядка операций).
- **Результат:** 24 бита, знаковый two's complement; полная шкала ±Vref/Gain. Константа: `ADS1220_RANGE_UINT = 0x7FFFFF`, опора `ADS1220_REF_MV_UINT = 2048` mV (внутренняя 2.048 V).

### 1.2 Регистры и MUX АЦП (Configuration Register 0)

Регистр 0 задаёт выбор входов и усиление:

| MUX (биты 7:4) | Значение | AINP   | AINN   | Назначение в проектах |
|----------------|----------|--------|--------|------------------------|
| MUX_0_1        | 0x00     | AIN0   | AIN1   | 4–20 mA: падение на шунте AIN0–AIN1 |
| MUX_0_2        | 0x10     | AIN0   | AIN2   | 4–20 mA N: AIN0–AIN2 |
| MUX_0_3        | 0x20     | AIN0   | AIN3   | Опорный резистор (Rref): ток → напряжение для PT/NTC |
| MUX_1_2        | 0x30     | AIN1   | AIN2   | TXA: дифференциальное напряжение термопары |
| MUX_1_AVSS     | 0x90     | AIN1   | AVSS   | Напряжение на AIN1 (single-ended): 10V (с делителем), NTC/PT датчик (напряжение на Rx) |
| MUX_2_AVSS     | 0xA0     | AIN2   | AVSS   | Аналогично для N-входа (AIN2) |

- **IDAC:** источник тока можно вывести на REFP0, REFN0, AIN0–AIN3 (конфиг регистр 2/3). Для резистивных датчиков используется **IDAC_REFP0** и внешняя коммутация: REFP0 → Rx → земля; падение на Rx измеряется AIN1 (или AIN2 для N).
- **Внутренний датчик температуры:** включается битом TS (регистр 1); результат в тех же 24 битах (интерпретация иная — см. TXA).

### 1.3 Чтение результата

**Корректный способ (используется в MP-02m, по референсу stm32mp02-1.2.7_6AI6AO):**

- Команду **RDATA (0x10) не отправлять**. Выполняется только **приём 3 байт** по SPI (24 SCLK): мастер передаёт 0xFF, 0xFF, 0xFF и одновременно принимает результат; первый принятый байт — MSB, третий — LSB.
- Результат: **rx_buf[0]** = MSB, **rx_buf[1]**, **rx_buf[2]** = LSB.
- Формула: `int32_t r = ((int8_t)rx_buf[0] << 16) | (rx_buf[1] << 8) | rx_buf[2];`

Использование RDATA и сдвиг на байт (rx_buf[1..3]) приводило к неверному значению и отрицательному r1 на резистивных каналах.

## 2. Аппаратный MUX (внешний мультиплексор платы)

Плата маршрутизирует входы IN1P…IN6P и IN1N…IN6N к входам АЦП AIN0–AIN3, REFP0, REFN0 и к вспомогательным узлам (делитель, midpoint, токовые ключи). Управление — через MCP23S17: **CS2** (ext1_porta, ext1_portb) и **CS3** (ext2_porta).

### 2.1 Разводка битов (MP-02m / stm32mp02)

**CS2 — Port A (ext1_porta):**

| Бит | Имя в коде      | Назначение |
|-----|-----------------|------------|
| 0   | sw_adc          | SW_ADC: P_IN1 (MUX_DB) подключается к REFP0 (1) или к REFN0/общей (0). Нужен для подачи тока в резистор (PT/NTC). |
| 4   | ain1            | Делитель 1:35 на пути к AIN1 (для 0–10 V). |
| 6   | ain2            | Делитель 1:35 на пути к AIN2. |
| 7   | mux3_en         | MUX3 enable (active low: 0 = включён). Каналы 4–6 N: IN4N…IN6N → AIN2. |

**CS2 — Port B (ext1_portb):**

| Бит | Имя в коде | Назначение |
|-----|------------|------------|
| 0   | mux2_en    | MUX2 enable (0 = включён). Каналы 4–6 P: IN4P…IN6P → AIN1. |
| 1   | mux_a0     | Адрес мультиплексора (A0). |
| 2   | mux_a1     | Адрес мультиплексора (A1). select 0..3 = комбинация A0,A1. |
| 5   | in4n       | Токовый ключ/путь для IN4 N (4–20 mA, резисторы N). |
| 6   | in4p       | Токовый ключ/путь для IN4 P (резисторы, 4–20 mA P). |
| 7   | midpoint   | MUX_DB подключается к VCC/2 (~1.65 V) для общего режима термопары (TXA). |

**CS3 — Port A (ext2_porta):** используется только для модуля 12AI (каналы 1–6).

| Бит | Имя в коде | Назначение |
|-----|------------|------------|
| 0   | in3p       | Ток/путь IN3 P. |
| 1   | in2n       | Ток/путь IN2 N. |
| 2   | in2p       | Ток/путь IN2 P. |
| 3   | in1n       | Ток/путь IN1 N. |
| 4   | mux1_en    | MUX1 enable (0 = включён). Каналы 1–3 P: IN1P…IN3P → AIN1. |
| 5   | in1p       | Ток/путь IN1 P. |
| 6   | in3n       | Ток/путь IN3 N. |
| 7   | mux4_en    | MUX4 enable (0 = включён). Каналы 1–3 N: IN1N…IN3N → AIN2. |

Для **каналов 4, 5, 6** выбор входа идёт только через CS2 (MUX2/MUX3, in4p/in4n, in5p/in5n, in6p/in6n). CS3 для них только выставляет начальное состояние (0x90 = mux1_en и mux4_en в 1, т.е. MUX1/MUX4 выключены).

### 2.2 Выбор канала (select_ch_pos / select_ch_neg)

- **Канал 1:** select=2, MUX1 on (P), MUX4 on (N). IN1P→AIN1, IN1N→AIN2.
- **Канал 2:** select=1, MUX1 on, MUX4 on. IN2P→AIN1, IN2N→AIN2.
- **Канал 3:** select=0, MUX1 on, MUX4 on. IN3P→AIN1, IN3N→AIN2.
- **Канал 4:** select=3, MUX2 on (P), MUX3 on (N). IN4P→AIN1, IN4N→AIN2.
- **Канал 5:** select=2, MUX2 on, MUX3 on. IN5P→AIN1, IN5N→AIN2.
- **Канал 6:** select=1, MUX2 on, MUX3 on. IN6P→AIN1, IN6N→AIN2.

Полярность P/N задаётся параметром `is_pos` при вызове `mux_setup(config, ch, is_pos)`: для P настраиваются divider/current для позитивного входа и select_ch_pos; для N — для негативного и select_ch_neg.

### 2.3 Порядок установки MUX в mux_setup()

1. **mux_reset()** — все мультиплексоры выключены (enable в 1), токи и делители выключены.
2. **adc_sw** — из config: подключение MUX_DB к REFP0 (для резистивных датчиков с током).
3. **midpoint** — из config: общий режим для термопары (VCC/2 на MUX_DB).
4. **input divider** — enable_input_divider: для P — ain1 (делитель 1:35 на AIN1), для N — ain2.
5. **current pos/neg** — enable_current_src: включение пути тока для выбранного канала (in1p…in6p или in1n…in6n).
6. **select_ch_pos(ch)** и **select_ch_neg(ch)** — выбор пары входов INxP→AIN1, INxN→AIN2.

После расчёта значений вызывается **adc_worker_load_mux_mcp()**: запись ext1_porta, ext1_portb в CS2, ext2_porta в CS3, затем задержка (10 ms в MP-02m) для установления аналоговой части.

## 3. Алгоритмы по типам датчиков

Общий цикл измерения (MP-02m / stm32mp02):

1. **FIRST_MUX_SET:** выбор канала (i, pos), вызов `ai_channel_start()` → `adc_worker_start(config1, config2, single_conv)` → mux_setup(config1), load_mux_mcp(), ads1220_setup(config1).
2. **FIRST_MUX_SET_WAIT:** ожидание MUX_SETTLE_TIME_MS (150 ms в MP-02m); при появлении DRDY — чтение и сброс (отбрасывание преобразования от setup); по истечении времени — ads1220_start().
3. **FIRST_ADC_RES_WAIT:** по DRDY — чтение, keep_first_result(). Если двойное измерение — adc_worker_second_start() (mux_setup(config2), load_mux_mcp(), ads1220_setup(config2)) → SECOND_MUX_SET_WAIT.
4. **SECOND_MUX_SET_WAIT:** аналогично: выдержка, при DRDY — сброс, затем ads1220_start().
5. **SECOND_ADC_RES_WAIT:** по DRDY — чтение, keep_second_result(), ai_channel_twice_compute() (расчёт base и value).
6. Возврат в FIRST_MUX_SET со сдвигом канала (update_input).

Для **одного** преобразования (single_conv) после шага 3 вызывается ai_channel_single_compute() и переход в FIRST_MUX_SET.

Ниже для каждого типа датчика указаны: количество преобразований, конфигурации config1/config2, состояние MUX и формула пересчёта.

---

### 3.1 Напряжение 0–10 V (VOLTAGE_10V)

- **Режим:** одно преобразование (single_conv).
- **Схема:** вход INxP (или INxN) через **делитель 1:35** подаётся на AIN1 (или AIN2). Максимум 10 V на входе платы → ~285 mV на AIN. Выбирается GAIN_4, чтобы уложиться в диапазон АЦП.

**Конфигурация (P):**

| Параметр              | Значение        |
|-----------------------|-----------------|
| gain                  | GAIN_4          |
| mux (ADS1220)         | MUX_1_AVSS      |
| ref                   | VREF_INT        |
| IDAC                  | NONE, OFF       |
| enable_input_divider  | **true**        |
| enable_current_src    | false           |
| enable_midpoint       | false           |
| adc_sw                | false           |

**MUX (положение):** выбран канал (select_ch_pos/neg), включён **делитель** (ain1 для P, ain2 для N). sw_adc и midpoint выключены, токи не используются.

**Формула:**  
`base [мкВ] = (1000 * VOLTAGE_DIVIDER * ref_mv * raw / ADS1220_RANGE_UINT) / gain`  
где `VOLTAGE_DIVIDER = 35`, ref_mv = 2048. Итоговая физическая величина (0–10 V) далее масштабируется в value по верхнему/нижнему пределу.

**Если показывает 0 при наличии напряжения:**  
- Убедитесь, что на канале задан тип датчика «0–10 В» и пределы (нижний/верхний) не равны 0.  
- Делитель 1:35 включается битами CS2 Port A: бит 4 (AIN1, канал P), бит 6 (AIN2, канал N). Если на плате логика реле/ключа инвертирована (1 = без делителя), в `mux_c.c` задайте `VOLTAGE_DIVIDER_PIN_INVERT` в 1 перед сборкой или добавьте в проект define `VOLTAGE_DIVIDER_PIN_INVERT=1`.  
- Проверьте осциллографом: при опросе канала 0–10 В на CS2 OLATA бит 4 (P) или бит 6 (N) должен быть установлен после вызова `mux_setup`.

---

### 3.2 Ток 4–20 mA (CURRENT_4_20MA)

- **Режим:** одно преобразование.
- **Схема:** ток проходит через внешний резистор; АЦП измеряет **дифференциальное** напряжение на этом резисторе (AIN0–AIN1 для P, AIN0–AIN2 для N). Источник тока АЦП не используется; enable_current_src в MUX включает путь прохождения внешнего тока через выбранный вход.

**Конфигурация (P):**

| Параметр              | Значение        |
|-----------------------|-----------------|
| gain                  | GAIN_1          |
| mux (ADS1220)         | MUX_0_1 (AIN0–AIN1) |
| ref                   | VREF_INT        |
| IDAC                  | NONE, OFF       |
| enable_input_divider  | false           |
| enable_current_src    | **true**        |
| enable_midpoint       | false           |
| adc_sw                | **true** (P) / false (N) |

**MUX:** выбран канал; для P включён **current_src** (inxp/inxn) и sw_adc = 1. Для N — current_src на негативном входе, sw_adc = 0.

**Формула:**  
`base [нА] = (1000 * 10 * ref_mv * raw / ADS1220_RANGE_UINT) / gain`.  
Далее пересчёт в миллиамперы и в value по пределам (4–20 mA).

---

### 3.3 NTC10K (двухпроводное сопротивление)

- **Режим:** два преобразования (config1, config2).
- **Схема (как в референсе):** внутренний IDAC АЦП через REFP0 подаёт ток 50 µA в резистор NTC. Первое измерение — напряжение на NTC (AIN1–AVSS или AIN2–AVSS). Второе — падение на опорном резисторе 1 kΩ (AIN0–AIN3) для вычисления тока. Используется **VREF_AVDD_AVSS** для расширенного диапазона.

**Config1 (напряжение на датчике):**

| Параметр     | Значение          |
|--------------|-------------------|
| gain         | GAIN_1            |
| mux          | MUX_1_AVSS (P) / MUX_2_AVSS (N) |
| routing      | IDAC_REFP0        |
| current      | IDAC_50_MU_A      |
| ref          | VREF_AVDD_AVSS    |
| enable_current_src | false (ток идёт через sw_adc→REFP0) |
| adc_sw       | **true** (P) / false (N) |

**Config2 (опорный резистор):**

| Параметр     | Значение          |
|--------------|-------------------|
| gain         | GAIN_32           |
| mux          | MUX_0_3 (AIN0–AIN3) |
| routing      | IDAC_REFP0        |
| current      | IDAC_50_MU_A      |
| ref          | VREF_AVDD_AVSS    |
| adc_sw       | true / false      |

**MUX:** для обоих замеров один и тот же канал (INxP или INxN). В config1: P_IN1 через sw_adc подключается к REFP0 (ток в NTC), P_IN2→AIN1 (напряжение на NTC). Делитель и midpoint выключены. Для второго замера MUX АЦП переключается на AIN0–AIN3 (внешний Rref 1 kΩ), MUX платы можно оставить тем же (ток по-прежнему через REFP0 и Rref).

**Формула сопротивления (0.01 Ом):**  
`base = 100000 * (res1 * GAIN2 / GAIN1) / res2`  
(res1 — напряжение на NTC, res2 — на Rref). Далее base переводится в температуру по таблице NTC10K.

### 3.4 PT1000 (двухпроводное сопротивление)

- **Режим:** два преобразования.
- **Схема:** аналогична NTC10K, но ток **1000 µA** и **VREF_INT**. Диапазон сопротивления PT1000 примерно 180–2120 Ом; GAIN_1 для датчика, GAIN_2 для опорного резистора.

**Config1:** gain=GAIN_1, mux=MUX_1_AVSS (P) или MUX_2_AVSS (N), IDAC_REFP0, 1000 µA, VREF_INT, adc_sw true/false.

**Config2:** gain=GAIN_2, mux=MUX_0_3, IDAC_REFP0, 1000 µA, VREF_INT.

**MUX:** как у NTC10K — выбор канала, sw_adc для подачи тока с REFP0 на датчик, без делителя и midpoint.

**Формула:** та же: `base = 100000 * (res1 * GAIN2 / GAIN1) / res2` (base в 0.01 Ом). Температура — по таблице PT1000.

---

### 3.5 PT100 (двухпроводное сопротивление)

- **Режим:** два преобразования.
- **Схема:** как PT1000, ток **1500 µA**. Диапазон сопротивления примерно 18–212 Ом; для датчика GAIN_4, для опоры GAIN_1.

**Config1:** gain=GAIN_4, mux=MUX_1_AVSS (P) или MUX_2_AVSS (N), IDAC_REFP0, 1500 µA, VREF_INT.

**Config2:** gain=GAIN_1, mux=MUX_0_3, IDAC_REFP0, 1500 µA, VREF_INT.

**MUX:** совпадает с PT1000/NTC10K (канал, sw_adc, без делителя).

**Формула:** та же; температура по таблице PT100.

---

### 3.6 TXA (термопара, K-тип и др.)

- **Режим:** два преобразования.
- **Схема:** первое — **дифференциальное** напряжение термопары (AIN1–AIN2); второе — **встроенная температура** АЦП для компенсации холодного спая. Для общего режима входов включается **midpoint** (VCC/2 на MUX_DB).

**Config1 (термопара):**

| Параметр     | Значение          |
|--------------|-------------------|
| gain         | GAIN_32           |
| mux          | **MUX_1_2** (AIN1–AIN2) |
| ref          | VREF_INT          |
| IDAC         | NONE, OFF         |
| enable_midpoint | **true**       |
| adc_sw       | false             |

**Config2 (холодный спай):**

| Параметр     | Значение          |
|--------------|-------------------|
| gain         | GAIN_32           |
| mux          | MUX_1_2           |
| ref          | VREF_INT          |
| **ts**       | **TS_ENABLED**    |

**MUX:** выбран канал; **midpoint = 1** (общий режим ~1.65 V); делитель и ток не используются. INxP→AIN1, INxN→AIN2 — дифференциальное измерение.

**Формула:**  
- res2 переводится в температуру холодного спая: `decideg = raw_to_decideg(res2)`.  
- Компенсация в микровольтах: `comp_uv = txa_decideg_to_uvolts(decideg)`.  
- `base [мкВ] = comp_uv + raw_to_int32_uv(res1, ref_mv, GAIN1)`.  
Далее base переводится в температуру по таблице термопары (K-тип и т.д.).

## 5. Связи алгоритмов при измерении

1. **Выбор канала (ch, pos):** определяется приложением (app_update_input). От ch и pos зависят только какие физические пины INxP/INxN выбираются в MUX (select_ch_pos/neg и биты inxp/inxn и т.д.). Конфигурации config1/config2 от типа датчика не зависят от номера канала — только от типа (voltage, current, NTC, PT, TXA) и полюса (P/N).

2. **Порядок операций:** MUX задаётся **до** ads1220_setup(), затем load_mux_mcp() и задержка. После выдержки MUX_SETTLE_TIME_MS запускается одно «полезное» преобразование (ads1220_start()). Так устраняется влияние преобразования, случайно стартующего при записи регистров АЦП.

3. **Двойное измерение:** один и тот же физический канал (ch, pos) измеряется дважды с разными config1 и config2. Между первым и вторым замером снова выполняется mux_setup(config2), load_mux_mcp(), ads1220_setup(config2), выдержка, ads1220_start(). Для резистивных датчиков config2 переключает только **внутренний MUX АЦП** на AIN0–AIN3 (опорный резистор); внешний MUX платы может оставаться в том же положении канала (ток продолжает идти через REFP0 и цепь датчика/опоры).

4. **Формула сопротивления:** во всех трёх проектах base (в 0.01 Ом) = `100000 * res1 * GAIN2 / GAIN1 / res2`. res1 — первый замер (напряжение на датчике), res2 — второй (напряжение на Rref). Константа 100000 соответствует опорному резистору 1 kΩ и масштабу 0.01 Ом.

5. **Референсы:** stm32mp02 и wiren-plc используют те же конфигурации MUX/ADC и те же формулы; в MP-02m принят способ чтения результата как в stm32mp02 (3 байта без RDATA), см. раздел 7.

## 6. Положение MUX по каналам и назначение выводов

### 6.1 Какие MUX включены для какого канала

После mux_reset() все MUX выключены (mux1_en, mux2_en, mux3_en, mux4_en установлены в 1). При выборе канала сбрасывается в 0 только нужная пара:

| Канал | Позитивный вход (P)      | Негативный вход (N)      | Включённые MUX      |
|-------|-------------------------|---------------------------|---------------------|
| 1     | IN1P → AIN1             | IN1N → AIN2               | MUX1 (CS3), MUX4 (CS3) |
| 2     | IN2P → AIN1             | IN2N → AIN2               | MUX1, MUX4          |
| 3     | IN3P → AIN1             | IN3N → AIN2               | MUX1, MUX4          |
| 4     | IN4P → AIN1             | IN4N → AIN2               | MUX2 (CS2), MUX3 (CS2) |
| 5     | IN5P → AIN1             | IN5N → AIN2               | MUX2, MUX3          |
| 6     | IN6P → AIN1             | IN6N → AIN2               | MUX2, MUX3          |

Select (A0, A1): 0 = (0,0), 1 = (1,0), 2 = (0,1), 3 = (1,1). Для каналов 1–3 используется MUX1/MUX4 (CS3), для 4–6 — MUX2/MUX3 (CS2).

### 6.2 Назначение битов при каждом типе датчика

- **0–10 V:** включается только **ain1** (P) или **ain2** (N) — делитель 1:35. Остальные биты после select — по умолчанию (mux enable сброшены для выбранного канала, sw_adc=0, midpoint=0, current_src=0).
- **4–20 mA:** для выбранного канала включается **inxp** (P) или **inxn** (N); для P также **sw_adc=1**. Делитель и midpoint выключены.
- **NTC10K / PT1000 / PT100:** **sw_adc=1** (P) или 0 (N) — подвод REFP0 к цепи датчика; **current_src=0** (ток задаётся IDAC АЦП через REFP0). Делитель и midpoint выключены. Включены только select и соответствующий mux2/mux3 или mux1/mux4.
- **TXA:** **midpoint=1** (общий режим); sw_adc=0, current_src=0, divider=0. Select и MUX как для выбранного канала — дифференциальное измерение AIN1–AIN2.

### 6.3 Соответствие кода и железа (MP-02m)

- **ext1_porta (CS2 OLATA):** bit0 sw_adc, bit4 ain1, bit6 ain2, bit7 mux3_en; остальные — in5p, in6p, in5n, in6n (биты 1,2,3,5).
- **ext1_portb (CS2 OLATB):** bit0 mux2_en, bit1 mux_a0, bit2 mux_a1, bit5 in4n, bit6 in4p, bit7 midpoint.
- **ext2_porta (CS3 OLATA):** bit0 in3p, bit1 in2n, bit2 in2p, bit3 in1n, bit4 mux1_en, bit5 in1p, bit6 in3n, bit7 mux4_en.

Для каналов 4–6 регистр CS3 после reset остаётся 0x90 (биты 4 и 7 установлены — MUX1 и MUX4 выключены). Активная коммутация для 4–6 идёт только через CS2.

## 7. Исправления для корректной работы измерений (MP-02m C)

Ниже зафиксированы изменения, внесённые для корректной работы программы измерений (референс: stm32mp02-1.2.7_6AI6AO).

### 7.1 Чтение результата ADS1220

- **Не использовать команду RDATA (0x10).** Выполнять только 3-байтовый обмен: `HAL_SPI_TransmitReceive` с tx = {0xFF, 0xFF, 0xFF}; результат в rx[0]=MSB, rx[1], rx[2]=LSB.
- Формула: `r = ((int8_t)rx[0] << 16) | (rx[1] << 8) | rx[2]`.
- Реализация: `ads1220_c.c` → `ads1220_on_ready_irq()`.

### 7.2 Режим SPI перед каждой транзакцией ADS1220

- ADS1220 работает в **режиме SPI Mode 1** (CPOL=0, CPHA=1). MCP23S17 на той же шине — в **Mode 0** (CPOL=0, CPHA=0).
- Перед каждым обращением к ADS1220 необходимо: отключить SPI, выставить режим под ADS1220 (`SET_SPI_MODE_FOR_ADS1X20`), включить SPI. Так после операций с MCP шина переключается обратно под АЦП.
- В драйвере MCP при poll-режиме перед транзакцией выставляется режим под MCP23S17.

### 7.3 Порядок записи MUX для модуля 12AI (каналы 4–6)

- Для каналов 4–6 на AIN1/AIN2 должны быть активны только **MUX2 и MUX3** (CS2); **MUX1 и MUX4 (CS3) должны быть выключены** (ext2_porta = 0x90).
- **Порядок записи в `adc_worker_load_mux_mcp()`:** сначала записать **CS3** (в т.ч. 0x90 для каналов 4–6), затем **CS2**. Если записать только CS2, не установив 0x90 в CS3, на AIN1 приходит конфликт (одновременно MUX1 и MUX2) → результат r1 отрицательный и температура неверная (например +24°C отображается как −30°C).
- Для значения 0x90 в CS3 перед записью CS2 выполнять **двойную запись 0x90 в CS3** с задержками (2 ms и 1 ms в текущей сборке; при нестабильности ch4–6 можно вернуть 5 ms и 3 ms).
- При инициализации модуля 12AI после сброса MCP на CS3 в OLATA дважды записать 0x90 с задержками, чтобы каналы 4–6 стартовали с выключенными MUX1/MUX4.

### 7.4 Время установки MUX после load_mux_mcp

- После записи CS2/CS3 в конце `adc_worker_load_mux_mcp()` выполняется задержка **3 ms** (ранее 10 ms) для установления аналоговой части. При нестабильных показаниях ch4–6 можно увеличить до 5–10 ms.

### 7.5 Нумерация chip select (MCP)

- В проекте используется общий тип `spi_cs_t` из `main.h`: **SPI_CS1 = 0, SPI_CS2 = 1, SPI_CS3 = 2, SPI_CS4 = 3**. Индексы соответствуют массивам `SPI_GPIO_Port[]` и `SPI_GPIO_Pin[]` (CS1→PA4, CS2→PA9, CS3→PA10, CS4→PA0).
- **ADS1220** подключён к **CS1 (PA4)**. В коде worker’а и MUX **не переопределять** номера CS: использовать именно `SPI_CS2` и `SPI_CS3` из `main.h`. Локальные `#define SPI_CS2 2` и `#define SPI_CS3 3` приводили к записи MUX в неправильные устройства (на пины CS3 и CS4), из-за чего read-back по CS3 давал 0x00/0xFF и измерения по каналу 4 были неверными.

## 8. Сокращение времени опроса каналов (ADS1220 + MUX)

### 8.1 Где уходит время

На один канал с **двумя** преобразованиями (резисторы, термопара) приходится:

| Этап | Было | Стало | Примечание |
|------|------|--------|------------|
| load_mux_mcp (первый) | 5+3+2+10 = 20 ms | 2+1+1+3 = 7 ms | CS3 0x90×2, CS2, финальная задержка |
| FIRST_MUX_SET_WAIT | 150 ms | **55 ms** | MUX_SETTLE_TIME_MS (ref stm32mp02: 55 ms) |
| Первое преобразование АЦП | ~50 ms (20 SPS) | ~50 ms | Зависит от DR_LVL (см. ниже) |
| load_mux_mcp (второй) | 20 ms | 7 ms | — |
| SECOND_MUX_SET_WAIT | 150 ms | **55 ms** | — |
| Второе преобразование АЦП | ~50 ms | ~50 ms | — |

Оценка на один канал (двойное измерение): было ~440 ms, стало ~228 ms. На полный цикл 12 каналов (6×P/N): было ~5.3 s, стало ~2.7 s.

### 8.2 Регулируемые параметры

- **MUX_SETTLE_TIME_MS** (`app_c.h`): 55 ms — как в референсе; при нестабильных ch4–6 можно поднять до 80–150 ms.
- **Задержки в adc_worker_load_mux_mcp()** (`adc_worker_task_c.c`): 2 ms, 1 ms, 1 ms, 3 ms; при сбоях по каналам 4–6 — увеличить (5, 3, 2, 10).
- **ADS1220 data rate**: в коде задаётся DR_LVL_0 (20 SPS, ~50 ms на преобразование). В `ads1220_set_config_1()` можно задать более высокий уровень (DR_LVL_1 = 45 SPS, DR_LVL_2 = 90 SPS и т.д.) — время одного преобразования уменьшится (~22 ms или ~11 ms), но возможен рост шума; требуется расширение `ads1220_config_t` полем data_rate и правка конфигов каналов.

### 8.3 Рекомендации

1. Сначала проверить работу при **MUX_SETTLE_TIME_MS = 55** и уменьшенных задержках в load_mux_mcp; при необходимости поднять только settle или только задержки после записи CS3/CS2.
2. Для дальнейшего ускорения — ввести в конфиг АЦП data rate и перейти на 45 или 90 SPS с проверкой качества измерений.
3. Каналы с одним преобразованием (0–10 V, 4–20 mA) уже быстрее: один settle + одно преобразование (~115 ms при 55 ms settle и 7 ms load).
