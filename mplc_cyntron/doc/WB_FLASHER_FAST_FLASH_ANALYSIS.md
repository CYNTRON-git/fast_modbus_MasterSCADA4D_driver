# Анализ быстрой прошивки wb-mcu-fw-flasher (Wiren Board)

Источник: https://github.com/wirenboard/wb-mcu-fw-flasher

## Как они укладываются в ~30 с на устройство

### 1. Минимальная пауза между кадрами

```c
void interFrameDelay(void) {
  // Workaround for issue FW-1187. Ensuring a minimal gap between frames.
  // A 100 µs delay is sufficient. sleep(0) has proven to be sufficient.
  sleep(0);
}
```

Между **каждым** блоком — только `sleep(0)` (минимальный отказ CPU), **никаких** `sleep(1)` или десятков миллисекунд. Блоки идут подряд сразу после ответа устройства.

### 2. Нет паузы 2 с после info-блока

В их коде после успешной отправки info-блока:
- `interFrameDelay()` (sleep(0))
- сразу вход в цикл `while (filePointer < filesize)` и отправка **первого** data-блока.

То есть они **не ждут 2 секунды** после info. Либо их бутлоадер стирает Flash очень быстро, либо принимает блоки в буфер параллельно со стиранием.

У нас: `ERASE_WAIT_AFTER_INFO_S = 2` и бутлоадер явно ждёт 2 с после info перед приёмом блоков (`BL_ERASE_INIT_DELAY_MS 2000`) — эти 2 с заложены в логику бутлоадера, убрать их только со стороны ПК нельзя.

### 3. Размер блока данных

- **WB:** `DATA_BLOCK_SIZE = 136` байт (68 регистров 0x10 на блок).
- **Мы:** 128 байт (64 регистра).

При одном и том же объёме прошивки у них меньше обменов (меньше кадров Modbus). У нас увеличение блока до 136 байт потребовало бы смены протокола и бутлоадера (0x2000, 68 регистров).

### 4. Скорость и таймаут

- По умолчанию у WB бутлоадер 9600 8N2; для быстрой прошивки они явно рекомендуют **115200** (`-B 115200`, с версии 1.1.4 бутлоадера).
- Таймаут ответа: `BL_MINIMAL_RESPONSE_TIMEOUT 5.0` с — не уменьшают до долей секунды, но и не добавляют искусственных задержек между блоками.

У нас скорость бутлоадера уже 115200 — ок.

### 5. Отправка блоков в цикле

Их цикл по сути:

```
отправить блок → interFrameDelay() (sleep(0)) → следующий блок
```

Повтор при ошибке (до MAX_ERROR_COUNT), без дополнительных `sleep` между попытками в нормальном проходе.

## Что можно перенести к нам без смены протокола/бутлоадера

| Что | У нас сейчас | Рекомендация |
|-----|--------------|--------------|
| Пауза после первого блока | 0.03 с (30 мс) | Уменьшить до 0 или до 5–10 мс по аналогии с WB (минимальный зазор). |
| Пауза после остальных блоков | 0 с | Оставить 0. |
| Пауза после info | 2 с → **1 с** | Сокращено до 1 с в прошивальщике и бутлоадере (BL_ERASE_INIT_DELAY_MS, FLASH_ERASE_INIT_DELAY_MS). |
| Таймаут ответа на блок | 1.5 с | Оставить или слегка уменьшить, если устройство стабильно отвечает быстрее. |

**Внесённые правки (кроме блока 136 байт):**
- Задержка после первого блока: **0** (было 30 мс).
- Пауза после info: **1 с** в прошивальщике и в бутлоадере (было 2 с) — экономия ~1 с.
- Между блоками: без пауз (0 с).

Чтобы ещё приблизиться к «не более 30 с» как у WB, можно было бы увеличивать размер блока (136 байт) со сменой протокола — не делалось по требованию.
