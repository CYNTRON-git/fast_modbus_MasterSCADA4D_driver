# Анализ драйвера AD5324

## Обнаруженные проблемы

### 1. **КРИТИЧЕСКАЯ ОШИБКА: Неправильный swap байтов в POLL режиме (строка 115)**

```c
value = ((value >> 8) & 0xFF) | ((value << 8) & 0xFF00);
```

**Проблема:** Эта формула НЕ выполняет swap байтов правильно. Она эквивалентна:
- `(value >> 8) & 0xFF` - старший байт
- `(value << 8) & 0xFF00` - младший байт, сдвинутый влево
- Результат: старший байт в младшей позиции, младший байт в старшей позиции

**Правильный swap:**
```c
value = ((value >> 8) & 0xFF) | ((value & 0xFF) << 8);
// или проще:
value = (value >> 8) | (value << 8);
```

**Сравнение с DMA версией:**
В DMA версии (строки 180-181) байты отправляются правильно:
```c
SPI_buf_write[0] = value >> 8;  // MSB первый
SPI_buf_write[1] = value & 0xFF; // LSB второй
```

### 2. **Проверка формата команды AD5324**

Согласно документации AD5324, формат 16-битной команды:
- **Бит 15:** Не используется (0)
- **Биты 14-13:** Выбор канала (A=00, B=01, C=10, D=11)
- **Бит 12:** nLDAC (0 = обновить все выходы, 1 = только регистр)
- **Бит 11:** nPD (0 = power-down, 1 = нормальный режим)
- **Биты 10-0:** Данные (12 бит для AD5324)

**Текущая реализация:**
```c
value |= (channel << 14);  // Бит 15-14: канал
value |= (1 << 13);        // Бит 13: nPD = 1
value |= (1 << 12);        // Бит 12: nLDAC = 1 (для каналов A, B, C)
value &= ~(1 << 12);       // Бит 12: nLDAC = 0 (для канала D)
```

**Проблема:** В коде используется бит 15 для канала, но согласно документации бит 15 должен быть 0, а канал в битах 14-13.

**Правильная реализация должна быть:**
```c
// Очистить старшие биты
value &= 0x0FFF;  // Оставить только 12 бит данных

// Установить канал в биты 14-13
value |= ((channel & 0x03) << 13);

// Установить nPD (бит 11) = 1
value |= (1 << 11);

// Установить nLDAC (бит 12)
if (channel == DAC_OUT_D) {
    value &= ~(1 << 12);  // nLDAC = 0 для канала D
} else {
    value |= (1 << 12);   // nLDAC = 1 для каналов A, B, C
}
```

### 3. **SPI режим**

Текущая реализация:
```c
SET_SPI_MODE_FOR_AD53X4()  // CPOL=0, CPHA=1 (Mode 1)
```

Это соответствует документации AD5324 (SPI Mode 1).

### 4. **Порядок байтов**

AD5324 ожидает MSB-first (старший байт первым). В DMA версии это реализовано правильно, но в POLL версии есть ошибка swap.

## Рекомендации по исправлению

1. **Исправить swap байтов в POLL режиме:**
   ```c
   // Удалить строку 115 и заменить на:
   uint8_t data[2];
   data[0] = (value >> 8) & 0xFF;  // MSB
   data[1] = value & 0xFF;          // LSB
   HAL_SPI_Transmit(&AD53X4_SPI_HAL, data, 2, 200);
   ```

2. **Исправить формат команды:**
   - Канал должен быть в битах 14-13, а не 15-14
   - nPD должен быть в бите 11, а не 13
   - nLDAC должен быть в бите 12 (правильно)

3. **Унифицировать код POLL и DMA версий** для избежания расхождений.
