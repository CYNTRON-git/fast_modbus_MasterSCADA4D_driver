# Сравнение прошивки в бутлоадере: stm32_modbus_bootloader-1.0.4 и MP-02m

## 1. stm32_modbus_bootloader-1.0.4 (референсный проект)

### Расположение в Flash
| Область        | Адрес           | Размер  |
|----------------|-----------------|---------|
| Bootloader     | 0x08000000      | 16 КБ   |
| Слот A (приложение) | 0x08004000 | 48 КБ   |
| Слот B (резерв)     | 0x0800C000 | 48 КБ   |
| Служебная      | 0x08014000      | 16 КБ   |

Бутлоадер в **начале** Flash; приложение — в двух слотах (A/B) для A/B обновления.

### Протокол обновления
- **Стек Modbus:** FreeModbus (RTU).
- **Функция обновления:** отдельный код функции **0x6C** (не стандартный 0x10).
- **Подфункции** (второй байт PDU):
  - `EraseFlash` — стереть слот приложения (одним вызовом).
  - `ProgramFlash` — записать блок: в кадре **4 байта offset** (LE) + **данные**; пишется в `FLASH_SLOT_A_BASE + offset`.
  - `GetChecksumFlash` / `GetChecksumFlash16` — проверка после прошивки.
  - `ProgramSerial` — запись серийного номера.
  - `ResetDevice` — сброс в приложение.

### Последовательность прошивки (референс)
1. Мастер шлёт запрос с функцией 0x6C, подфункция `EraseFlash` → устройство стирает слот A целиком и отвечает статусом в том же кадре.
2. Мастер многократно шлёт 0x6C + `ProgramFlash` с разными `offset` и блоками данных (размер блока задаётся длиной PDU).
3. По желанию: проверка CRC, запись серийника, сброс.

### Код работы с Flash (референс)
- **Файлы:** `Modules/bootloader/flash.c`, `flash.h`.
- **Стирание:** `flash_erase_app()` → `flash_erase_slot(FLASH_SLOT_A_BASE)` → цикл по страницам 2 КБ, в каждой:
  - `flash_unlock()` → `while(flash_is_busy());` → PER/AR/STRT → `while(flash_is_busy());` → сброс PER.
- **Запись:** `flash_write_app_data(offset, data, size)` → запись полусловами через `flash_write_hword()`.
- **Таймаутов** в циклах `while(flash_is_busy())` **нет** — при зависании Flash возможен бесконечный цикл.
- **Выполнение из RAM:** код flash.c **не** вынесен в RAM; при стирании/записи в том же банке Flash на STM32F0 процессор не может читать инструкции из Flash и может «зависнуть» (тот же эффект, что был в MP-02m до введения .ramfunc).

### Регистры Modbus (holding)
- 0xFFF0 — активация бутлоадера (запись 0x55AA).
- 0xFFF1…0xFFF5 — статус, прогресс, версия, размер/CRC32 прошивки (чтение).

## 2. Текущий проект MP-02m (bootloader в конце Flash)

### Расположение в Flash
| Область     | Адрес       | Размер  |
|-------------|-------------|---------|
| Векторы     | 0x08000000  | 2 КБ    |
| Приложение  | 0x0800800   | до 0x0803B600 |
| Bootloader  | 0x08038000  | 32 КБ   |

Бутлоадер в **конце** Flash; одно приложение без слотов A/B.

### Протокол обновления
- **Стек Modbus:** nanoMODBUS (только сервер, 0x03/0x04/0x10).
- **Стандартная функция 0x10** (Write Multiple Registers):
  - **Регистр 0x1000** (16 регистров = 32 байта) — **info-блок**: сигнатура 12 байт (ASCII) + размер прошивки 4 байта (LE) + резерв 16 байт. По приёму: проверка размера и сигнатуры (EEPROM), **стирание области приложения**, сохранение размера и сброс счётчика offset.
  - **Регистр 0x2000** (64 регистра = 128 байт) — **блок данных** (как BL_PROTOCOL_MAX_BLOCK_SIZE в референсе). Последовательная запись по `flash_offset`; после последнего блока — запись сигнатуры в EEPROM (при первой прошивке).
- Отдельно: регистр 129 — вход в бутлоадер; 1004 — переход в приложение.

### Последовательность прошивки (MP-02m)
1. Мастер читает рег. 290 (сигнатура) и 330 (версия бутлоадера).
2. **Один** кадр 0x10 на адрес 0x1000 с 32 байтами (info): сигнатура + размер. Устройство стирает Flash приложения и отвечает 0x10 (эхо start/count).
3. Мастер шлёт серию кадров 0x10 на адрес 0x2000 по 128 байт данных (блоки по 64 регистра).
4. По окончании — при необходимости запись в рег. 1004 для перехода в приложение.

### Код работы с Flash (MP-02m)
- **Файлы:** `bootloader/Core/Src/flash_bl.c`, `flash_bl.h`.
- **Стирание:** `flash_bl_erase_region(FLASH_APP_START, size_aligned)` — цикл по страницам с **таймаутом** `BL_FLASH_ERASE_TIMEOUT_MS` и проверкой ошибок Flash (WRPERR, PGERR).
- **Запись:** `flash_bl_write_block(addr, data)` — 64 полуслова (128 байт) за один вызов.
- **Выполнение из RAM:** функции `flash_wait_ready`, `flash_bl_erase_region`, `flash_bl_write_block` помечены `section(".ramfunc")`, копируются в RAM при старте (startup) и выполняются из RAM. Это устраняет зависание при BSY Flash (когда CPU не может читать код из Flash).

### Приём длинного кадра 0x10
- В `uart_bl.c` для функции 0x10 кадр не считается законченным после 8 байт: ожидается полная длина **9 + byte_count** байт (с общим таймаутом 2 с на ожидание остатка), чтобы принять info-блок (41 байт) одним кадром.

### EEPROM
- Сигнатура устройства (12 байт) хранится в EEPROM (CAT24C02) по смещению 240; записывается **в конце** прошивки (при первой загрузке), а не при приёме info-блока.

## 3. Сводное сравнение

| Аспект              | stm32_modbus_bootloader-1.0.4     | MP-02m (текущий)                    |
|---------------------|-----------------------------------|-------------------------------------|
| Modbus              | FreeModbus, своя функция 0x6C     | nanoMODBUS, стандартный 0x10       |
| Формат «старт»      | Отдельная подфункция EraseFlash   | Один info-блок 0x1000 (32 байта)   |
| Блок данных         | ProgramFlash: offset + данные (до 128 B) | 0x2000: блоки по 128 байт (64 reg), порядок по offset |
| Расположение BL     | Начало Flash (0x08000000)         | Конец Flash (0x08038000)           |
| Слоты A/B           | Да (два слота прошивки)           | Нет (одно приложение)              |
| Стирание            | Целиком слот                      | Область приложения по размеру      |
| Таймауты в Flash    | Нет                               | Есть (erase/write)                 |
| Код Flash в RAM     | Нет (риск зависания при BSY)      | Да (.ramfunc)                      |
| EEPROM/сигнатура    | Отдельная подфункция ProgramSerial| В info-блоке; запись в EEPROM в конце |
| Флешер (ПК)         | Свой протокол под 0x6C            | Modbus 0x10, рег. 0x1000/0x2000   |

Референсный проект использует **собственный** протокол (0x6C + подфункции) и другую раскладку памяти (слоты A/B); текущий MP-02m использует **только стандартный Modbus 0x10** и фиксированные регистры 0x1000/0x2000, с выполнением кода стирания/записи из RAM и приёмом полного кадра 0x10 для info-блока.

## 4. Детальное сравнение: алгоритм приёма, передачи и записи

### 4.1 Размер блока (как в рабочем референсе)

- **Референс:** `BL_PROTOCOL_MAX_BLOCK_SIZE = 128` (bootloader_protocol.h). Пакет DATA_BLOCK — до 128 байт.
- **MP-02m:** `BL_DATA_BLOCK_SIZE = 128`, регистр 0x2000 — 64 регистра = 128 байт. Совпадает.

### 4.2 Алгоритм приёма блока

| Шаг | Референс (0x5AA5-пакеты) | MP-02m (Modbus 0x10) |
|-----|---------------------------|----------------------|
| Приём | UART → сборка пакета в буфер → разбор маркера/CRC | UART → кадр в буфер → nmbs_server_poll → callback Write Multiple Registers |
| Валидация | Номер блока, размер 1..128, CRC16 | Адрес 0x2000, количество 64, CRC Modbus в кадре |
| Реакция на блок | Сразу в callback: `flash_write_data(write_address, packet->data, packet->data_length)` | Callback только копирует в `data_block_buf`, выставляет `data_block_pending`; стирание/запись — в main loop |

В референсе запись в Flash выполняется **в том же контексте**, что и приём (в обработчике пакета). В MP-02m запись **отложена** в main loop, чтобы не держать долго стек/прерывания и выполнять Flash из RAM в одном месте.

### 4.3 Порядок: стирание → запись

- **Референс:** При START_TRANSFER вызывается `flash_erase_slot(current_slot_address)` — стирается **весь слот** до приёма первого DATA_BLOCK. Дальше только запись блоков по порядку.
- **MP-02m:** При приёме info — только выставляется `erase_pending`; в main выполняется неблокирующее ожидание 2 с, затем `info_received = true`. **Страницы не стираются заранее:** стирание одной страницы (2 КБ) выполняется **перед первой записью в эту страницу** (при `page_addr != last_erased_page_addr`). Затем на следующей итерации цикла — запись блока. Так уменьшается время до первого ответа и не блокируется приём на время полного стирания.

### 4.4 Работа с памятью Flash

| Проверка | Референс | MP-02m |
|----------|---------|--------|
| Граница записи | Слот A/B: `FLASH_SLOT_A_END` / `FLASH_SLOT_B_END` | `FLASH_APP_WRITE_END = BL_CODE_ORIGIN` (0x08038000) — запись/стирание не заходят в область бутлоадера |
| Адрес начала приложения | FLASH_SLOT_A_BASE (0x08004000) или B | FLASH_APP_START (0x0800800) |
| Выравнивание записи | Полуслова (16 бит) | Полуслова; адрес в `flash_bl_write_block` проверяется на `(address & 1) == 0` |
| Размер блока при записи | `packet->data_length` (1..128) | Всегда 128 байт в буфер; последний неполный блок дополняется 0xFF до 128 байт (исправлено: раньше последний блок отклонялся, если размер не кратен 128) |

### 4.5 Выполнение кода при работе с Flash

- **Референс:** `flash.c` выполняется из Flash; циклы `while(flash_is_busy())` без таймаута. На части STM32F0 при BSY чтение Flash может блокировать шину → риск зависания.
- **MP-02m:** Стирание и запись вызываются через `_sramfunc` (код в секции `.ramfunc`, скопирован в RAM при старте). В циклах не опрашивается FLASH->SR (избегаем блокировки шины), используются задержки в RAM. Вокруг вызова `ram_flash(...)` — `__disable_irq()` / `__enable_irq()`.

### 4.6 Порядок байт в регистрах и в Flash

- **Flasher / .fw:** Регистр = big-endian (старший байт первым в кадре Modbus). `payload_block_to_registers`: `(block[i] << 8) | block[i+1]`. В .fw файл пишется как 16-бит big-endian слова (`struct.pack(">H", w)`).
- **Бутлоадер:** В callback 0x2000: `data[i*2] = (registers[i] >> 8)`, `data[i*2+1] = (registers[i] & 0xFF)` — в буфере старший байт первым. В `flash_bl`: `half = (data[i*2] << 8) | data[i*2+1]` — запись в Flash полусловами в том же порядке. STM32 Flash — little-endian по адресам; записанное полуслово совпадает с образом приложения (образ строится от 0x0800800 с тем же порядком байт).

### 4.7 Последний блок (размер не кратен 128)

- **Референс:** Блоки могут быть разной длины (1..128); последний блок приходит с `data_length = size % 128` (или 128, если размер кратен 128). Записывается ровно `data_length` байт.
- **MP-02m:** Флешер шлёт `(size + 127) // 128` блоков по 128 байт; последний блок дополняется нулями/0xFF в образе. В бутлоадере: принимается блок, если `flash_offset < flash_total_bytes`; в буфер копируется `min(128, flash_total_bytes - flash_offset)` байт, остаток буфера до 128 байт заполняется 0xFF; в Flash пишется полный блок 128 байт. Так последний неполный образ записывается корректно.
