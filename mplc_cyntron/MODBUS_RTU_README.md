# Протокол Modbus RTU с поддержкой быстрого Modbus

## Описание

Реализован протокол Modbus RTU с поддержкой расширения "Быстрый Modbus" от Wiren Board. Протокол обеспечивает:

1. **Совместимость с обычным Modbus RTU** - работа с любыми устройствами Modbus RTU
2. **Поддержку быстрого Modbus** - использование расширенных возможностей для устройств Wiren Board:
   - Быстрое сканирование шины (broadcast запросы)
   - Механизм событий (events) для быстрой реакции на изменения
   - Разрешение коллизий адресов
   - Арбитраж при одновременных ответах

## Структура файлов

- `modbus_rtu_protocol.h` - заголовочный файл с определением классов протокола
- `modbus_rtu_protocol.cpp` - реализация протокола
- `fast_modbus_protocol.h/cpp` - обертка для интеграции с существующей структурой проекта

## Основные классы

### ModbusRtuChannel

Класс канала для работы с Modbus RTU устройствами. Наследуется от `api::ScadaChannel`.

#### Настройки канала

```cpp
std::string port_name;           // Имя COM порта ("/dev/ttyUSB0" или "COM1")
uint32_t baud_rate;              // Скорость (9600, 19200, 38400, 57600, 115200)
uint8_t data_bits;               // Биты данных (7 или 8)
uint8_t stop_bits;               // Стоп-биты (1 или 2)
uint8_t parity;                  // Четность (0=none, 1=odd, 2=even)
uint32_t response_timeout_ms;    // Таймаут ответа в мс
uint32_t inter_frame_delay_ms;   // Задержка между кадрами в мс

// Настройки быстрого Modbus
bool enable_fast_modbus;         // Включить поддержку быстрого Modbus
uint32_t event_poll_interval_ms; // Интервал опроса событий (50 мс по умолчанию)
bool auto_scan_enabled;          // Автоматическое сканирование устройств
```

#### Методы для работы с регистрами (стандартный Modbus RTU)

- `ReadHoldingRegisters()` - чтение регистров хранения
- `ReadInputRegisters()` - чтение входных регистров
- `ReadCoils()` - чтение дискретных выходов
- `ReadDiscreteInputs()` - чтение дискретных входов
- `WriteSingleRegister()` - запись одного регистра
- `WriteMultipleRegisters()` - запись нескольких регистров
- `WriteSingleCoil()` - запись одного дискретного выхода
- `WriteMultipleCoils()` - запись нескольких дискретных выходов

#### Методы быстрого Modbus

- `ScanBus()` - быстрое сканирование шины (broadcast запрос)
- `RequestEvents()` - запрос событий от устройств
- `ConfigureEvent()` - настройка события для регистра
- `ResolveAddressConflict()` - разрешение коллизии адресов
- `CheckFastModbusSupport()` - проверка поддержки быстрого Modbus устройством

### ModbusRtuProtocol

Класс протокола, управляющий каналами. Наследуется от `api::ScadaProtocol`.

## Принцип работы

### Автоматическое определение поддержки быстрого Modbus

При первом обращении к устройству протокол автоматически проверяет поддержку быстрого Modbus:

1. Отправляется broadcast запрос сканирования
2. Если устройство отвечает - оно поддерживает быстрый Modbus
3. Если нет ответа - используется обычный Modbus RTU

### Работа с событиями

Если включен быстрый Modbus (`enable_fast_modbus = true`):

1. Каждые `event_poll_interval_ms` миллисекунд отправляется broadcast запрос событий
2. Устройства с событиями отвечают с приоритетом (арбитраж по адресу)
3. События обрабатываются и обновляют переменные канала

### Сканирование шины

Метод `ScanBus()` отправляет broadcast запрос, на который отвечают все устройства с поддержкой быстрого Modbus, сообщая:
- Свой адрес
- Серийный номер
- Поддержку быстрого Modbus

Это позволяет быстро обнаружить все устройства на шине и выявить коллизии адресов.

## Пример использования

```cpp
// Создание канала (обычно делается через API MPLC)
ModbusRtuChannel* channel = new ModbusRtuChannel();
channel->port_name = "/dev/ttyUSB0";
channel->baud_rate = 9600;
channel->enable_fast_modbus = true;
channel->auto_scan_enabled = true;
channel->Init();

// Чтение регистров
std::vector<uint16_t> values;
if (channel->ReadHoldingRegisters(1, 0, 10, values)) {
    // Обработка значений
}

// Быстрое сканирование шины
std::vector<ModbusDevice> devices;
if (channel->ScanBus(devices)) {
    for (const auto& dev : devices) {
        // Обработка найденных устройств
    }
}

// Запрос событий
std::vector<ModbusEvent> events;
if (channel->RequestEvents(events)) {
    for (const auto& event : events) {
        // Обработка событий
    }
}
```

## Совместимость

Протокол полностью совместим с:
- Стандартным Modbus RTU (любые устройства)
- Расширением "Быстрый Modbus" от Wiren Board
- Работой на одной шине устройств с разной поддержкой протоколов

Если устройство не поддерживает быстрый Modbus, протокол автоматически переключается на обычный Modbus RTU для работы с этим устройством.

## Обработка ошибок

Протокол обрабатывает следующие ошибки:
- Ошибки открытия/закрытия порта
- Таймауты при чтении/записи
- Ошибки Modbus (неверная функция, адрес, значение)
- Ошибки CRC
- Ошибки парсинга ответов

Все ошибки устанавливают состояние неисправности канала через `SetFaultState()`.

## Технические детали

### Формат кадров Modbus RTU

Стандартный формат:
- Адрес устройства (1 байт)
- Код функции (1 байт)
- Данные (N байт)
- CRC16 (2 байта, младший байт первый)

### Расширенные функции быстрого Modbus (Wiren Board)

Протокол использует адрес **0xFD** для расширенных команд и основную команду **0x46** с субкомандами:

**Сканирование шины:**
- `0x46` + `0x01` - Начало сканирования
- `0x46` + `0x02` - Продолжение сканирования
- `0x46` + `0x03` - Ответ на сканирование
- `0x46` + `0x04` - Конец сканирования

**События:**
- `0x46` + `0x10` - Запрос событий
- `0x46` + `0x11` - Передача событий
- `0x46` + `0x12` - Ответ если события отсутствуют
- `0x46` + `0x18` - Настройка отправки событий

**Работа с устройствами по серийному номеру:**
- `0x46` + `0x08` - Отправка стандартной команды
- `0x46` + `0x09` - Ответ на стандартную команду

Подробная документация: [Wiren Board Modbus Extension Protocol](https://github.com/wirenboard/wb-modbus-ext-scanner/blob/main/docs/protocol.ru.md)

### Арбитраж

При одновременных ответах на broadcast запросы используется арбитраж:
- После отправки команды мастер ждет **3.5 фрейма молчания** на шине
- Устройства с меньшим серийным номером имеют приоритет
- Устройства с большим серийным номером откладывают ответ
- Это позволяет избежать коллизий на шине RS-485
- Время арбитража зависит от скорости передачи (при 9600 бод ~4 мс, при 115200 бод ~0.33 мс)

Протокол интегрирован в структуру проекта через:
