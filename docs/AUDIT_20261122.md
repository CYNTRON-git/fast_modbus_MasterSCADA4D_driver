## Дополнение: полный проект и native-сериализация

Добавлен проект SA02m_FastModbus: 3 линии, 14 устройств, 502 входных канала. Карты сверены с исходниками MR, ДТВ, СЭ‑02М и 87 строками Modbus Tag из cPCOmini_Carel.xlsx. AI MR знаковые; многословные регистры MR/СЭ читаются младшим словом вперёд. Состав шин пока основан на историческом снимке 11.11 и требует свежего экспорта координатора.

Полный локальный прогон обнаружил особенность SDK 35699: native-экспорт исключает нулевые и false-настройки из карт Channel/IOModule. Подстановка RegType=3 вместо отсутствующего значения превращала Coils=0 в Input Registers. Исправлено: числовые настройки каналов трактуются с нулевым default, Scale задаётся явно и проверяется на ненулевое значение. Для обычного Modbus применяется положительный DisableEvents=true: false-флаг EnableEvents не переживал экспорт. Отсутствующий адрес модуля считается ошибкой, а не адресом 1.

Полный тест использует отдельный native-проект Win64 и три TCP loopback-имитатора. Он проверяет все 502 значения/качества, signed/unsigned, масштабы и порядок слов, события от 13 устройств, изменение Carel через обычное чтение, отсутствие адресных FC70 к Carel, отсутствие команд записи и остановку своих процессов. Значения событий отличаются от RTU readback, поэтому обычный опрос не может подменить доказательство события. Итоговые статусы и SHA берутся из native-runtime-results.json, а не из этого описания процедуры. Физическая работа пока не подтверждена.

- DLL SHA256: `9e12a0295497810ee16a6f66b197881cdc2f93653f0cf6eb880af55dcbca8c33`. В собственных исходниках предупреждений MSVC не найдено; предупреждения поставщика SDK сохранены в полном журнале.

MasterPLC при потере связи сохраняет последнее прочитанное значение с качеством `UncertainNoCommunicationLastUsableValue` (0x408F0000), хотя драйвер передаёт BadCommunicationError. Это проверено совместно с Fault=True; последнее значение нельзя считать актуальным только потому, что оно численно осталось на экране.

Общий MCP-проверяющий инструмент имеет номера типов из другой базы. Для нового проекта использован аудит, который получает идентификаторы Own и типов узлов из его собственных TYPES, плюс нативная проверка модели и физическая проверка Firebird.

## Комплект и воспроизведение

В архиве подготовки находятся Windows DLL, нативный экспорт проекта и пользовательской библиотеки, исходники, журналы и JSON результатов, план HIL, рецепты ARM и SHA256 manifest. Экспорт проекта и библиотеки выполнен штатным API IDE; живые FDB не копировались файловыми командами.

Для локального повторения: `tools/build_windows.py --tests`, `tests/transport_tests.py`, `tools/build_windows.py`; создание нового проекта — `dotnet build tools/project/BenchProject.csproj -c Release`, затем `tools/project/inspect_project.ps1 -Create`; аудит и запуск — `tools/stage_runtime.py`, `tests/runtime_acceptance.py`. Последние два скрипта допускают только проверенный loopback-профиль с отключённой записью. Нужны установленная MasterSCADA 35699 и указанный в сборочном скрипте локальный комплект compiler/SDK; vendor SDK в Git не включён.

Для hardware-профиля UART, скорость, адрес, serial и версия runtime берутся из свежей передачи стенда; предложение 12AI@12, SN 0E0A61A9, COM4=/dev/ttyS5, 115200 8N1 не заменяет разрешение port coordinator. Поддержана запись по изменению; принудительная повторная запись того же значения отдельным импульсом пока не реализована.
